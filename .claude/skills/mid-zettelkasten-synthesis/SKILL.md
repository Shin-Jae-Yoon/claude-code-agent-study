# Mid Zettelkasten Synthesis

챕터별 정리본을 재료로 사용하되 결과를 챕터 안에 격리하지 말고 저장소 공통 제텔카스텐에 누적하라.

## 입력과 출력

- 입력: 한 챕터의 팀원별 정리본 2개 이상 또는 사용자가 지정한 Markdown 파일들
- 일반적인 입력: `chapters/chN/*/정리본.md`
- 기본 출력: 저장소 루트의 `zettelkasten/`

항상 원본 정리본을 보존하라. 새 내용을 만들기 전에 `zettelkasten/README.md`, `notes/`, `maps/`, 관련 `syntheses/`를 읽어 기존 지식망과 비교하라.

## 디렉터리 역할

```text
zettelkasten/
├── README.md
├── notes/
├── maps/
└── syntheses/
```

- `notes/`: 독립적으로 이해할 수 있는 주장, 질문, 실천법, 긴장 또는 사례 하나를 파일 하나로 저장하라.
- `maps/`: 관련 원자 메모를 주제와 관점에 따라 묶는 탐색 지도를 저장하라. 지식의 원문을 중복하지 마라.
- `syntheses/`: 이번 입력에서 무엇을 발견하고 어떤 메모를 생성·갱신했는지 기록하라.
- `README.md`: 전체 진입점과 주요 지도 링크를 유지하라.

## 합성 절차

1. 입력 파일의 경로와 작성자를 목록화하라.
2. 각 문서에서 주장, 질문, 경험, 사례와 실패를 분리하라. 단순 키워드는 태그나 지도 후보일 뿐 원자 메모로 만들지 마라.
3. 표현이 달라도 의미가 같은 내용을 묶되 다음 신호를 구분하라.
   - **반복**: 둘 이상의 독립 문서에서 등장
   - **강조**: 한 문서에서 근거·사례와 함께 깊게 다룸
   - **긴장**: 문서 간 해석이나 경험이 다름
   - **독창**: 한 문서에만 있지만 후속 가치가 높음
4. 반복 횟수를 중요도의 신호로만 사용하라. 반복됐다는 이유로 사실이나 팀 합의로 단정하지 마라.
5. [원자 메모 스키마](references/note-schema.md)에 따라 기존 `notes/` 전체와 비교하라.
   - 같은 주장: 새 파일을 만들지 말고 기존 메모에 출처와 근거를 추가하라.
   - 겹치지만 다른 주장: 별도 메모를 만들고 관계를 설명하는 링크를 추가하라.
   - 충돌하는 주장: 양쪽을 보존하고 `contrasts` 관계로 연결하라.
6. 원자 메모끼리 관련, 보완, 대조, 선행, 적용 관계를 표준 Markdown 상대 링크로 연결하라.
7. 관련 메모가 3개 이상 모이면 `maps/`에 주제 지도를 생성하거나 기존 지도를 갱신하라.
8. 입력 단위가 챕터라면 `syntheses/chN.md`에 처리 결과를 기록하라. 챕터가 아니면 `syntheses/YYYYMMDD-source-slug.md`를 사용하라.
9. 주요 지도의 링크와 간단한 설명을 `zettelkasten/README.md`에 반영하라.

## 파일명과 링크

- 원자 메모는 `short-descriptive-slug.md` 형식의 구체적인 영문 소문자 kebab-case를 사용하라.
- 파일명을 안정적인 식별자로 취급하고 같은 주제의 파일을 임의로 바꾸지 마라.
- `[[...]]` 위키 링크와 별도 YAML `id`를 사용하지 마라.
- 모든 링크는 GitHub에서 이동 가능한 표준 Markdown 상대 링크로 작성하라.
- 모든 주장에 원본 파일과 작성자를 출처로 남기고 작성자 이름을 추측하지 마라.

## 마무리 점검

- 새 메모가 실제로 하나의 독립적인 주장 또는 질문만 담는지 확인하라.
- 모든 상대 링크가 실제 파일을 가리키는지 확인하라.
- 의미가 같은 중복 메모와 대소문자만 다른 파일명이 없는지 확인하라.
- 연결이 없는 메모는 관련 메모 또는 지도에 연결하거나 독립 상태인 이유를 합성 기록에 적어라.
- Python, Node.js 또는 외부 패키지를 요구하지 마라.
