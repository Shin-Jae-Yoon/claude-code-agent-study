# Mid Study Deep Dive

학습 내용을 반복 요약하지 말고 질문과 현재 근거로 확장하라. 최신·현재·최근이라는 내용을 다룰 때는 반드시 실행 시점에 웹을 조회하라.

## 입력과 출력

- 입력: `chapters/chN/README.md`, `chapters/chN/zettelkasten/`, 개인 정리본 또는 사용자가 붙여넣은 내용
- 선택: 관심 기술, 적용 환경, 질문 난이도, 비교 기준일
- 기본 저장: 챕터가 특정되면 `chapters/chN/deep-dive.md`; 아니면 대화로만 제공

여러 파일을 받으면 공통 주장과 관점 차이를 먼저 파악하되 기존 내용을 길게 다시 쓰지 마라.

## 조사 절차

1. 핵심 주장, 암묵적 전제, 미해결 질문을 추출하라.
2. [탐구 렌즈](references/research-lenses.md)에서 관련 렌즈만 골라 질문을 만들라.
3. 오래 유지되는 개념과 현재성이 있는 제품·API·도구 동작을 구분하라.
4. 현재성이 있는 내용은 웹에서 다시 확인하라.
   - 공식 문서, 공식 엔지니어링 글, 표준, 원 논문, 공식 저장소와 릴리스 노트를 우선하라.
   - 검색 결과 요약만 믿지 말고 원문을 열어 확인하라.
   - Claude Code는 Anthropic 공식 문서와 릴리스 기록, Codex는 OpenAI 공식 문서를 우선하라.
5. 책 또는 노트의 기준 시점 이후 바뀐 명령어, 기본값, 기능과 권장 패턴을 찾으라.
6. 출처가 충돌하면 각 주장과 날짜의 차이를 표시하라.
7. 확인된 사실, 출처에 근거한 추론, 토론용 가설을 분리하라.

## 출력

### 1. 이해 점검 질문

- 사실 확인 질문 2~3개
- "왜 이렇게 설계됐는가" 질문 2~3개
- 코드·설계에 적용하는 질문 2~3개
- 각 질문 아래에 짧은 답안 포인트를 `<details>`로 제공하라.

### 2. 더 생각해볼 거리

- 숨은 전제
- 반례 또는 실패 조건
- 트레이드오프
- 팀 토론용 논쟁 질문

### 3. 지금은 무엇이 달라졌나

| 책·노트의 내용 | 현재 상태 | 바뀐 점 | 실무 영향 | 근거 날짜 |
|---|---|---|---|---|

확인된 변경이 없으면 억지로 만들지 말고 조사했으나 중요한 변경을 찾지 못했다고 쓰라.

### 4. 후속 탐구 경로

- 15분: 빠르게 읽을 공식 자료
- 1시간: 재현하거나 비교할 실험
- 반나절: 프로젝트 적용 과제

### 5. 참고 자료

각 자료에 제목, 링크, 발행·업데이트 날짜, 읽어야 하는 이유를 한 줄로 적어라. 최신 사실에는 가까운 위치에 출처를 연결하라.

## 규칙

- 질문 수보다 구체성과 검증 방법을 우선하라.
- "AI가 중요해지고 있다" 같은 일반론을 피하라.
- 최신·현재·최근이라는 표현에는 기준 날짜를 표시하라.
- 블로그나 2차 자료만으로 제품 동작을 단정하지 마라.
- 찾지 못한 사실을 추측하지 말고 조사 범위와 불확실성을 적어라.
- 기존 `mid-study-wrapup`의 회고·KPT 영역을 대신하지 마라.
