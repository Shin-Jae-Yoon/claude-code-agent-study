# 탐색은 범위를 좁혀 가며 앞 단계 결과를 다음 입력으로 넘긴다

"이 시스템 전체를 설명해 줘"라고 한 번에 묻는 대신, 관련 파일 찾기 → 파일 간 상호작용 읽기 → 실행 흐름 추적처럼 단계적으로 좁힌다. 각 단계의 결과가 다음 단계의 입력이 된다. 한 번에 전부 요구하면 필요 없는 내용까지 컨텍스트에 들어온다.

## 근거와 출처

- [2장 재윤 정리](../../chapters/ch2/jaeyoon/정리본.md): 탐색 순서를 Glob·Grep으로 파일 찾기 → Read로 상호작용 읽기 → 실행 흐름 추적으로 정리하고, 인증 시스템 예시로 질문을 단계별로 제시했다. "처음부터 '인증 시스템 전체를 설명해 줘'라고 묻는 것보다 탐색 범위를 좁혀 가는 편이 컨텍스트를 절약한다."
- [2장 홍섭 정리](../../chapters/ch2/hongseob/정리본.md): 같은 원리를 `탐색 → 분석 → 심화` 3단계로 정리하고 실제 사례를 붙였다. 1장의 `@경로` vs 풀경로 토큰 실험이 그 순서로 진행됐다 — 더미 파일로 크기 측정(탐색) → 토큰 차이 측정 10,500 대 175(분석) → "큰 파일은 풀경로" 결론(심화). "한 번에 다 시키는 게 아니라, 앞 단계 결과를 다음 단계 입력으로 넘기는 게 핵심."
