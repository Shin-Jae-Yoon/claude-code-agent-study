# SKILL.md 분량 기준은 세 사람이 다르게 본다

같은 "200줄"이라는 숫자를 세 정리본이 각각 **실무 기준 / 보수적 안전선 / 잘못된 수치**로 처리했다. 방향(길면 나눠라)에는 이견이 없지만, 어떤 숫자를 규약으로 삼을지, 아니 숫자를 쓸지 말지부터 갈린다.

## 근거와 출처

- [3장 홍섭 정리](../../chapters/ch3/hongseob/정리본.md) — **실무 기준으로 채택.** 200줄을 SOLID의 SRP로 해석하고 자기 스킬을 실제로 쟀다. `pre-chapter-prep` 66줄, `nova-api-planner` 68줄은 양호, `humanize-korean` 257줄은 "오케스트레이터라 길어짐, 리팩터 후보"로 분류했다.
- [3장 재윤 정리](../../chapters/ch3/jaeyoon/정리본.md) — **보수적 안전선으로 유지.** 공식문서가 500줄임을 확인하고도 교재 기준(영문 200줄 / 한국어 150줄)을 유지했다. 근거는 "방향은 같고 임계값만 다르다. 노트 쪽이 더 보수적이므로 노트 기준을 지키면 공식 기준도 자동으로 만족한다".
- [3장 준호 정리](../../chapters/ch3/junho/Chapter%2003.%20에이전트%20스킬.md) — **잘못된 수치로 분류.** "커뮤니티에서 도는 숫자 중 공식 근거가 없는 것"으로 표에 넣고 공식 기준은 500줄이라고 명시했다. 여기서 한 발 더 나갔다 — "500줄은 상한이지 목표가 아니다. (…) 사내 가이드에 숫자를 못박으면 '150줄 안에 넣었으니 됐다'가 되면서 정작 중요한 판단(이 문단이 토큰값을 하는가)이 생략된다."

## 열린 질문

- 팀 규약에 숫자를 넣을 것인가. 넣는다면 어느 숫자이고, 넣지 않는다면 "이 문단이 토큰값을 하는가"를 어떻게 리뷰 가능한 형태로 만들 것인가?
