워크플로와 설정

개인 정리본(재윤·홍섭)을 4개 고정 렌즈로 종합 · 이번 주 병합 참여 2인 (준호 2장 정리본 없음)

탐색→계획→구현→검증→커밋↻ 반복

참여자별 · 원문 보존

재윤탐색→계획→구현→검증 워크플로 + 도구·확장 지형도
  • 중심 메시지 — 좋은 결과는 탐색→계획→구현→검증→커밋에서. 검증 결과에 따라 앞 단계로 되돌아 반복.
  • 탐색 — "전체 설명" 대신 Glob/Grep → Read → 실행 흐름으로 범위를 좁혀 컨텍스트 절약.
  • 세 도구 지형도 (경쟁 아님, 서로 다른 병목): Graphify=코드+문서 지식 그래프(AST 로컬, 관계 근거 EXTRACTED/INFERRED), CodeGraph=에이전트용 SQLite 코드 인덱스(호출 경로·blast radius, MCP), Ouroboros=명세 우선 계획 도구(소크라테스 질문, Ambiguity ≤0.2).
  • 계획·구현 — 플랜 모드(--permission-mode plan, Shift+Tab), 점진 개발 3축, TDD, /compact·/clear, worktree.
  • 확장 도구 — Skill=지식 확장 / 서브에이전트=능력 확장 / MCP / Hooks / Plugins(배포 단위).
  • 실측 관점 — 이 저장소 settings 대부분 비어 있음({}) → 각 개념을 "지금 어디에 도입할지" 위치로 매핑.
홍섭워크플로 실측 + 설정·환경변수 실전
  • 워크플로 핵심 — 탐색→분석→심화. 앞 단계 결과를 다음 입력으로. 사례: @경로 vs 풀경로 토큰 실측 10,500 vs 175.
  • settings 임의 key 실험(실측) — 미정의 key를 넣어도 거부 없이 무시되고 실행(exit 0). "strict" 문서 표현과 실제 동작의 간극. $schema로 편집 단계에서 잡음.
  • 점진 개발 단위 — 정량("몇 줄")보다 atomic sub-requirement. 핵심: "좋은 프롬프트보다 좋은 피드백 루프가 더 중요".
  • settings 위계(실측) — 관리자 > CLI 인자 > 로컬 > 프로젝트 > 사용자. 위가 이김.
  • 스프링부트 .env 문제 정답 — 원인 이중(셸도 스프링도 .env 자동 로드 안 함). 정답은 settings.json의 env → 모든 subprocess에 OS 환경변수 주입. yaml 수정 아님.
  • 실전 2안 — A) settings.local.json env 이관(이중 관리) vs B) 빌드 명령 set -a; . ./.env; set +a(추천). CLAUDE.md 규칙으로 자동화.

4 렌즈 · 종합

공통

둘 다 짚은 것

  • 단계형 워크플로 + 앞 단계 → 다음 단계 이월 (재윤 탐색→계획→구현→검증 / 홍섭 탐색→분석→심화)
  • 점진 개발과 피드백 루프의 중요성 (재윤 3축·TDD / 홍섭 "프롬프트보다 피드백 루프")
  • settings.json 설정 위계 — 관리자 > 프로젝트 > 로컬 > 사용자, 구체적·상위가 덮어씀
  • env 키로 환경변수 주입 (재윤 후보 항목 / 홍섭 스프링부트 정답)
  • CLAUDE.md / CLAUDE.local.md / ~/.claude/CLAUDE.md 3계층
  • .env·민감값 보호 (재윤 permissions.deny·Bash 우회 / 홍섭 gitignore·커밋 금지)

흥미로운 것

인상 깊었던 개념·경험 (누가)

  • 홍섭임의 key를 넣어도 거부 없이 무시되고 실행된다는 실측 — 문서 "strict"와 실제의 간극
  • 홍섭.env 문제의 이중 원인(셸+스프링)과 "yaml 수정이 아니라 OS 환경변수 주입" 통찰
  • 홍섭@경로 vs 풀경로 토큰 실측(10,500 vs 175)으로 워크플로 뒷받침
  • 재윤세 도구를 "경쟁" 아닌 서로 다른 병목으로 배치한 프레이밍
  • 재윤Ouroboros 수치 종료 조건(Ambiguity ≤0.2 등)이 내부 운영 기준임을 명시한 태도
  • 재윤Skill=지식 확장 / 서브에이전트=능력 확장 구분

갈린 관점

같은 걸 다르게 봄

  • 워크플로 단계 명명 — 재윤: 계획·검증을 명시적 단계로(플랜 모드·TDD) / 홍섭: 분석·심화에 압축
  • 점진 개발 단위 — 홍섭: 정량 기준에 회의적(atomic sub-requirement) / 재윤: 3축으로 절차화
  • env를 다루는 깊이 — 홍섭: 실전 결론까지(A vs B, B 추천) / 재윤: 개념 소개 + 충돌 우선순위는 열린 질문으로
