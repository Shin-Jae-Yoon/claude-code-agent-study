## 1-1 클로드 코드와 에이전틱 코딩

### 에이전틱 루프 (Agentic loop)

작업 하나를 받으면 Claude는 세 단계를 돈다.

1. **컨텍스트 수집 (gather context)** — 파일 검색·읽기, 명령 실행 결과 확인
2. **행동 (take action)** — 파일 편집, 명령 실행, 커밋
3. **검증 (verify results)** — 테스트·빌드·린트 실행해서 결과 확인

이 셋은 칼같이 나뉘지 않고 섞인다. 요청 성격에 따라 도는 모양이 달라진다.

- 코드베이스 질문 → 1단계만
- 버그 수정 → 세 단계를 여러 번 반복
- 리팩터링 → 검증 비중이 커짐

각 도구 호출의 **결과가 다음 단계 판단의 입력**이 된다. 이게 "에이전틱"의 핵심이고, 단순 코드 자동완성과 갈리는 지점.

**루프를 구성하는 두 축**

| 축 | 역할 |
|---|---|
| **모델(Model)** | 추론. 코드 이해, 작업 분해, 판단. `/model`로 전환 |
| **도구(Tools)** | 행동. 도구가 없으면 Claude는 텍스트만 뱉음 |

**에이전틱 하네스(Agentic harness)** ⚠️
공식 용어집에 새로 정리된 개념. **Claude Code = 하네스, Claude = 그 안의 모델**.
하네스가 제공하는 것: 파일 접근, 셸 실행, 권한 게이팅, 메모리 로딩, 그리고 행동을 이어 붙이는 루프 자체.

**턴(Turn)** ⚠️
용어집에 추가됨. 사용자가 메시지를 보낸 시점부터 Claude가 응답을 마칠 때까지가 1턴. **그 안에 도구 호출은 몇 개가 들어가도 상관없음.** `Stop` 훅은 턴 끝에 발화한다. 세션 = 여러 턴, 에이전틱 루프 = 한 턴 안의 이야기.

**사용자도 루프의 일부**

- `Esc` — 즉시 중단. 실행 중인 도구 호출이 취소되고 다음 지시를 기다림. 컨텍스트는 유지됨
- **교정 입력 후 Enter** — 실행 중인 도구를 멈추지 않고 전달. 현재 동작이 끝나는 즉시 반영
- 작업 중 입력한 메시지는 **큐에 쌓임**(interrupt가 아님). `Up` 키로 회수 가능

### 에이전틱 코딩 (Agentic coding)

공식 정의: AI가 파일을 읽고, 명령을 실행하고, 자율적으로 변경을 가하는 워크플로. 사용자는 지켜보거나, 방향을 틀거나, 자리를 비울 수 있다. **텍스트로 답만 주고 적용은 사람이 하는 챗봇형 어시스턴트와 대비되는 개념.**

인라인 코드 어시스턴트와의 결정적 차이는 **시야 범위**다. "인증 버그 고쳐줘" 한 마디에 Claude는 관련 파일을 검색하고, 여러 파일을 읽어 맥락을 잡고, 파일들을 걸쳐 일관되게 수정하고, 테스트를 돌려 검증하고, 요청하면 커밋까지 한다. 현재 열려 있는 파일만 보는 도구로는 불가능한 동작이다.

**검증 루프 (Verification loop)** ⚠️
용어집에 새로 들어온, 챕터1에서 제일 중요한 신규 개념.

> 세션이 "그럴듯해 보이는" 상태가 아니라 **실제로 끝났는지**를 스스로 판단하는 방법.

Claude에게 스스로 돌릴 수 있는 검사(테스트 스위트, 빌드, 스크린샷 비교)를 주면, 한 번 시도하고 멈추는 대신 검사가 통과할 때까지 반복한다. 검증 루프가 없으면 **"다 됐다"고 판단하는 주체가 에이전트 자신뿐**이라 사용자가 검증 루프 역할을 떠안게 된다.

검증을 거는 강도는 4단계로 나뉜다.

| 방법 | 강제력 | 비용 |
|---|---|---|
| 프롬프트에 "테스트 돌리고 고쳐" 포함 | 약 | 없음 |
| `/goal <조건>` — 매 턴 별도 평가자가 조건 충족 확인 | 중 | 설정 약간 |
| `Stop` 훅 — 스크립트가 통과할 때까지 턴 종료 차단 (연속 8회 차단 시 강제 종료) | 강 | 스크립트 작성 |
| 검증용 서브에이전트 / 워크플로 — 새 컨텍스트의 모델이 결과를 반증 시도 | 강 | 토큰 |

### 컨텍스트 윈도우

세션의 작업 기억. **여기에 뭐가 들어가는지 아는 게 클로드 코드 숙련도의 대부분이다.**

**아무것도 입력하기 전에 이미 로드되는 것들** (대략적 토큰 규모, 상황에 따라 변동)

| 항목 | 대략 | 터미널에 보이나 |
|---|---|---|
| 시스템 프롬프트 | ~4.2K | ✗ |
| Auto memory (`MEMORY.md`) ⚠️ | ~0.7K | ✗ |
| 환경 정보 (cwd, 플랫폼, 셸, git 여부) | ~0.3K | ✗ |
| MCP 도구 **이름만** (스키마는 지연 로딩) ⚠️ | ~0.1K | ✗ |
| Skill **설명 한 줄씩** (본문은 호출 시) | ~0.5K | ✗ |
| `~/.claude/CLAUDE.md` | ~0.3K | ✗ |
| 프로젝트 `CLAUDE.md` | ~1.8K | ✗ |

핵심: **사용자 프롬프트는 이미 로드된 양에 비하면 아주 작다.** 컨텍스트 대부분은 프로젝트 지식이지 사용자가 친 글자가 아니다.

**작업하면서 쌓이는 것**

- 파일 읽기 — 압도적 비중. 파일 하나에 1~3K 토큰
- path-scoped rule — 매칭되는 파일을 읽는 순간 자동 로드
- 훅 출력 — `hookSpecificOutput.additionalContext` 필드만 컨텍스트에 들어감 (exit 0의 평범한 stdout은 디버그 로그로만)
- 명령 출력, Claude의 응답과 diff
- 서브에이전트 → **자기 컨텍스트에서 작업하고 요약만 반환**. 6,100 토큰 읽고 420 토큰만 돌려주는 식

**확인 방법**: `/context` — 카테고리별 사용량을 격자로 시각화하고 최적화 제안까지 준다. `/context all`로 항목별 상세.

### 컨텍스트 윈도우 관리 전략

#### 자동 압축(compaction)이 하는 일

한계에 가까워지면 자동으로: **① 오래된 도구 출력부터 비움 → ② 그래도 부족하면 대화를 요약**.
요청 내용과 핵심 코드 스니펫은 보존되지만, **대화 초반에 준 상세 지시는 날아갈 수 있다.**

#### ⚠️ 압축 후 무엇이 살아남는가 (표로 외워둘 것)

| 로딩 방식 | 압축 후 |
|---|---|
| 시스템 프롬프트, output style | 그대로 (메시지 히스토리가 아님) |
| **프로젝트 루트 `CLAUDE.md`**, `paths:` 없는 rules | **디스크에서 다시 주입됨** |
| **Auto memory** | **디스크에서 다시 주입됨** |
| `paths:` 프론트매터가 있는 rules | 유실. 매칭 파일을 다시 읽어야 복귀 |
| 하위 디렉토리의 중첩 `CLAUDE.md` | 유실. 해당 디렉토리 파일을 다시 읽어야 복귀 |
| 호출됐던 skill 본문 | 재주입되나 **skill당 5,000 / 총 25,000 토큰 상한**, 오래된 것부터 탈락 |
| Skill 목록(설명) | **재주입 안 됨**. 실제 호출한 skill만 보존 |
| 훅 | 해당 없음 (코드로 실행, 컨텍스트 아님) |

실무 함의 두 가지:
1. **대화로만 준 지시는 압축에서 사라진다** → 지속돼야 하면 `CLAUDE.md`에 넣어라.
2. skill 본문은 잘릴 때 **앞부분부터 남긴다** → `SKILL.md`의 중요한 지시는 위쪽에 배치.

#### 능동적으로 쓸 수 있는 수단

```bash
/compact focus on the auth bug fix   # 초점을 지정해 요약. 자동 압축이 추측하는 대신 내가 고름
/autocompact 500k                    # ⚠️ 자동 압축 발동 지점을 직접 설정 (v2.1.221+)
/clear                               # 무관한 작업으로 넘어갈 때. 새 세션 시작 (이전 세션은 /resume으로 복귀 가능)
/btw <질문>                          # ⚠️ 사이드 질문. 답변이 대화 히스토리에 안 들어감
```

- **서브에이전트에 조사 위임** — "use subagents to investigate X". 파일 읽기가 내 컨텍스트를 안 먹음
- **`CLAUDE.md`에 압축 지시 넣기** — `## Compact Instructions` 섹션에 "압축 시 수정된 파일 목록과 테스트 명령은 항상 보존" 같은 식
- **`CLAUDE.md`는 200줄 이하 목표** — 넘으면 path-scoped rule이나 skill로 분리
- **`disable-model-invocation: true`** — 사용자만 호출하는 skill은 설명조차 컨텍스트에 안 올라감
- **MCP tool search** ⚠️ — 기본적으로 MCP 도구 스키마가 지연 로딩. 이름만 올라가고, Claude가 실제로 쓸 때 스키마를 가져옴. `ENABLE_TOOL_SEARCH=false`로 전부 선로딩 가능

#### ⚠️ 1M 토큰 컨텍스트

Fable 5, Sonnet 5, Opus 4.6 이상, Sonnet 4.6에서 **100만 토큰 컨텍스트** 지원. Sonnet 5는 `[1m]` 변형 선택 없이 기본 1M. 압축은 큰 창에서도 동일하게 동작한다. 플랜별 가용성은 `model-config#extended-context` 참조.

#### 압축 스래싱 에러 ⚠️

파일 하나가 너무 커서 요약 직후 컨텍스트가 다시 가득 차면, 몇 번 시도 후 자동 압축을 **중단하고 에러를 띄운다**(무한 루프 방지).

### 다섯 가지 접근 영역과 핵심 기능

> ⚠️ **책과 현재 문서의 프레이밍이 다르다.** 책은 (파일시스템 / 터미널 / 웹 / MCP 서버 / 에디터 컨텍스트)로 나눈다. 현재 공식문서는 **내장 도구를 5개 범주**로 나누고, "Claude가 접근할 수 있는 것"은 별도 목록으로 둔다. 둘 다 알아두면 발표할 때 대조하기 좋다.

#### (A) 공식문서의 내장 도구 5범주

| 범주 | 할 수 있는 것 | 실제 도구 이름 |
|---|---|---|
| **File operations** | 파일 읽기·편집·생성·이동 | `Read` `Write` `Edit` `NotebookEdit` |
| **Search** | 패턴으로 파일 찾기, 정규식 내용 검색 | `Glob` `Grep` |
| **Execution** | 셸 명령, 서버 기동, 테스트, git | `Bash` `PowerShell` `Monitor` |
| **Web** | 웹 검색, 문서 fetch, 에러 메시지 조회 | `WebSearch` `WebFetch` |
| **Code intelligence** ⚠️ | 편집 후 타입 에러·경고 확인, 정의로 점프, 참조 찾기 | `LSP` (code intelligence 플러그인 필요) |

이 밖에 오케스트레이션 도구: `Agent`(서브에이전트), `Skill`, `AskUserQuestion`, `Task*`(태스크 목록), `EnterPlanMode`/`ExitPlanMode`, `EnterWorktree`, `EndConversation` 등.

#### (B) "Claude가 접근하는 것" 목록

- **프로젝트** — 현재 디렉토리와 하위. 권한을 주면 그 밖도
- **터미널** — 사용자가 칠 수 있는 명령이면 Claude도 칠 수 있음
- **git 상태** — 현재 브랜치, 미커밋 변경, 최근 커밋 히스토리
- **`CLAUDE.md`** — 매 세션 시작에 로드되는 사용자 작성 지시
- **Auto memory** ⚠️ — Claude가 스스로 적어둔 학습. `MEMORY.md`의 앞 200줄 또는 25KB
- **설정한 확장** — MCP 서버, skills, subagents, Claude in Chrome

#### (C) 책의 5영역을 현재 문서에 매핑하면

| 책 | 현재 대응 |
|---|---|
| 파일시스템 | File operations + Search 범주. 권한 규칙은 `Read(...)` / `Edit(...)` 경로 패턴 |
| 터미널 | Execution 범주. Windows에선 `PowerShell` 도구가 별도로 존재 ⚠️ |
| 웹 | `WebFetch`(도메인별 승인, 15분 캐시, 추출 프롬프트로 손실 발생) + `WebSearch`(세션당 200회 상한 ⚠️) |
| MCP 서버 | `.mcp.json`(프로젝트 공유) / `~/.claude.json`(개인). tool search로 지연 로딩 ⚠️ |
| 에디터 컨텍스트 | ⚠️ 이제 두 갈래로 구체화됨: **LSP 도구**(code intelligence 플러그인)와 **IDE 내장 MCP 서버**(VS Code / JetBrains 확장) |

**주의할 도구 동작 몇 가지**

- `WebFetch`는 **손실이 있는 설계**다. 페이지를 가져와 마크다운으로 바꾼 뒤 **작은 모델에 추출 프롬프트를 돌린 결과**를 Claude가 받는다. "그 페이지에 그 내용 없더라"가 실은 "추출 프롬프트가 그걸 안 물어봤다"일 수 있다. 원문이 필요하면 Bash로 `curl`.
- `Grep`은 `.gitignore`를 **존중**하고, `Glob`은 **존중하지 않는다**. (`CLAUDE_CODE_GLOB_NO_IGNORE=false`로 변경 가능)
- `Bash`는 **명령마다 별도 프로세스**다. `export`한 환경변수는 다음 명령에 안 남는다. `cd`는 프로젝트 디렉토리 안이면 유지된다. 셸 startup 파일의 alias와 함수는 세션 시작 시 캡처해 적용된다.

### 엔터프라이즈 환경에서의 클로드 코드

#### 관리 설정(managed settings)이 전달되는 4가지 경로 ⚠️

우선순위 순. **첫 번째로 비어 있지 않은 설정을 반환하는 소스 하나만 적용**된다 (병합이 아님, 단 아래 예외).

| 방식 | 위치 | 우선순위 | 플랫폼 |
|---|---|---|---|
| **Server-managed** ⚠️ | claude.ai 관리자 콘솔, 또는 자체 호스팅 Claude apps gateway | 최상 | 전체 |
| plist / 레지스트리 정책 | macOS `com.anthropic.claudecode` / Windows `HKLM\SOFTWARE\Policies\ClaudeCode` | 상 | mac, Win |
| 파일 기반 | mac `/Library/Application Support/ClaudeCode/managed-settings.json`<br>Linux·WSL `/etc/claude-code/managed-settings.json`<br>Win `C:\Program Files\ClaudeCode\managed-settings.json` | 중 | 전체 |
| Windows 사용자 레지스트리 | `HKCU\SOFTWARE\Policies\ClaudeCode` | 하 | Win |

예외 두 가지: **cross-source lock 키**(샌드박스 allowlist 잠금 등)는 어느 관리자 소스가 설정해도 적용되고, **`env` 블록은 키 단위로 병합**된다(v2.1.223+).

Server-managed는 인증 시점에 배포되고 세션 중 **매시간 갱신**된다. 엔드포인트 인프라가 필요 없다는 게 장점. Teams/Enterprise 플랜 필요.

#### 무엇을 강제할 수 있나

| 통제 영역 | 주요 키 |
|---|---|
| 도구·명령 허용/차단 | `permissions.allow` / `permissions.deny` |
| 권한 잠금 (`--dangerously-skip-permissions` 봉쇄) | `allowManagedPermissionRulesOnly`, `permissions.disableBypassPermissionsMode` |
| OS 레벨 샌드박스 + 도메인 allowlist | `sandbox.enabled`, `sandbox.network.allowedDomains` |
| 조직 전역 `CLAUDE.md` (개인이 제외 불가) | 관리 정책 경로의 파일, 또는 `claudeMd` 키 |
| MCP 서버 통제 | `allowedMcpServers`, `deniedMcpServers`, `allowManagedMcpServersOnly`, `managed-mcp.json` |
| 플러그인 마켓플레이스 통제 | `strictKnownMarketplaces`, `blockedMarketplaces`, `disableSideloadFlags` |
| 커스터마이징 잠금 (skill/agent/hook/MCP를 플러그인 경유로만) | `strictPluginOnlyCustomization` |
| 로그인 강제 (방법 + 조직) | `forceLoginMethod`, `forceLoginOrgUUID` |
| 모델 제한 | `availableModels`, `enforceAvailableModels` |
| 버전 하한 / 허용 범위 | `minimumVersion` / `requiredMinimumVersion`, `requiredMaximumVersion` |

**권한 규칙과 샌드박스는 다른 레이어다.** `WebFetch`를 막아도 Bash가 열려 있으면 `curl`로 아무 URL이나 갈 수 있다. 그 구멍은 샌드박스의 네트워크 도메인 allowlist가 OS 레벨에서 막는다.

#### 가시성 / 데이터

- **OpenTelemetry** — 세션·도구·토큰 지표를 SIEM이나 관측 백엔드로 export (전 프로바이더)
- **Analytics 대시보드** — Teams/Enterprise는 `claude.ai/analytics`, Console은 `platform.claude.com/claude-code`
- **비용 통제** — 관리자 설정의 spend limit, Console은 워크스페이스 한도, gateway는 사용자별 한도
- **ZDR (Zero Data Retention)** — 요청 완료 후 아무것도 저장 안 함. Enterprise 자격 계정
- Team / Enterprise / API / 클라우드 프로바이더 플랜에서 **코드와 프롬프트로 모델을 학습시키지 않음**

#### 확인 방법

개발자 머신에서 `/status` → **Status 탭의 `Setting sources` 줄**에 `Enterprise managed settings (remote|plist|HKLM|HKCU|file)`로 어느 소스가 적용됐는지 표시된다.

## 1-2 클로드 코드 설치

### ⚠️ 설치 방법 — 네이티브 설치가 권장으로 바뀜

책은 npm 전역 설치와 Node.js 18+ 를 전제로 할 텐데, **현재 공식 권장은 네이티브 인스톨러**다.

```bash
# macOS / Linux / WSL — 권장
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex

# Windows CMD
curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd
```

**대안 설치 방법**

| 방식 | 명령 | 자동 업데이트 |
|---|---|---|
| Homebrew (stable) | `brew install --cask claude-code` | ✗ 수동 |
| Homebrew (latest) | `brew install --cask claude-code@latest` | ✗ 수동 |
| WinGet | `winget install Anthropic.ClaudeCode` | ✗ 수동 |
| apt / dnf / apk | 서명된 저장소 등록 후 설치 | ✗ 시스템 업그레이드로 |
| npm | `npm install -g @anthropic-ai/claude-code` | 조건부 |

**⚠️ Node.js 관련 정정**
- npm 패키지는 **Node.js 22 이상** 필요 (v2.1.198부터). 구버전이면 `EBADENGINE` 경고만 뜨고 설치는 됨
- **하지만 설치되는 건 네이티브 바이너리다.** `claude` 실행 파일 자체는 Node를 쓰지 않는다
- 즉 "Node.js 18+ 가 전제조건"은 더 이상 정확하지 않다
- `sudo npm install -g`는 **금지** (권한 문제 + 보안 위험)

**시스템 요구사항**

- macOS 13.0+ / Windows 10 1809+ 또는 Server 2019+ / Ubuntu 20.04+ / Debian 10+ / Alpine 3.19+
- RAM 4GB+, x64 또는 ARM64
- 셸: Bash, Zsh, PowerShell, CMD
- `ripgrep` 보통 동봉 (Alpine 등 musl 계열은 별도 설치 후 `USE_BUILTIN_RIPGREP=0`)

**Windows 3가지 선택지**

| 방식 | 필요 조건 | 샌드박스 | 언제 |
|---|---|---|---|
| 네이티브 Windows | 없음 (Git for Windows는 선택) | ✗ | Windows 네이티브 프로젝트 |
| WSL 2 | WSL 2 | ✓ | Linux 툴체인, 샌드박스 실행 필요 시 |
| WSL 1 | WSL 1 | ✗ | WSL 2 불가 시 |

Git for Windows가 없으면 Bash 도구 대신 **PowerShell 도구**를 쓴다. Git Bash 경로를 못 찾으면 `settings.json`의 `env.CLAUDE_CODE_GIT_BASH_PATH`로 지정.

**설치 확인**

```bash
claude --version   # → 2.1.211 (Claude Code) 형태
```

### 인증 설정

```bash
claude       # 최초 실행 → 브라우저 로그인
/login       # 세션 내 재인증 / 계정 전환
/logout      # 로그아웃 (첫 실행 셋업 상태도 초기화됨)
```

브라우저가 안 열리면 `c`를 눌러 URL 복사. WSL2·SSH·컨테이너에서는 브라우저가 로컬 콜백 서버에 못 닿아 **코드를 보여주고 터미널에 붙여넣게** 한다.

**계정 유형** — 무료 Claude.ai 플랜은 Claude Code를 못 쓴다.

- Claude Pro / Max
- Claude for Teams / Enterprise
- Claude Console (관리자 초대 필요, `Claude Code` 롤 또는 `Developer` 롤)
- Amazon Bedrock / Google Cloud Agent Platform / Microsoft Foundry
- ⚠️ 자체 호스팅 **Claude apps gateway** — 회사 SSO로 로그인

**⚠️ 자격증명 우선순위 (7단계)** — 왜 로그인했는데 다른 계정으로 나가는지 설명해주는 표

1. 클라우드 프로바이더 (`CLAUDE_CODE_USE_BEDROCK` / `_VERTEX` / `_FOUNDRY`)
2. `ANTHROPIC_AUTH_TOKEN` (Bearer 헤더)
3. `ANTHROPIC_API_KEY` (X-Api-Key 헤더)
4. `apiKeyHelper` 스크립트 출력
5. `CLAUDE_CODE_OAUTH_TOKEN`
6. Anthropic 프로필 / 페더레이션 자격증명
7. `/login`으로 받은 구독 OAuth

> 구독이 있는데 `ANTHROPIC_API_KEY`가 환경에 있으면 **승인 후 API 키가 이긴다.** 만료·비활성 조직의 키면 인증 실패가 난다. `unset ANTHROPIC_API_KEY` 후 `/status`로 확인.

**자격증명 저장 위치**

- macOS: 암호화된 Keychain
- Linux: `~/.claude/.credentials.json` (모드 0600)
- Windows: `%USERPROFILE%\.claude\.credentials.json`

**CI용 장기 토큰**

```bash
claude setup-token   # 1년짜리 OAuth 토큰 출력 (저장 안 함, 복사해서 쓸 것)
export CLAUDE_CODE_OAUTH_TOKEN=<token>
```
모델 요청만 가능. Remote Control이나 claude.ai 커넥터는 못 씀. `--bare` 모드는 이 변수를 읽지 않으니 CI에서 bare를 쓰면 `ANTHROPIC_API_KEY`를 써야 한다.

**⚠️ 로그인 만료 경고** (v2.1.203+)
만료 3일 전부터 시작 시 `Your login expires in 3 days · run /login to renew` 표시. `/status`의 `Login` 행에서도 확인 가능(v2.1.210+). 무인 실행되는 백그라운드 세션엔 이게 중요하다 — 자격증명이 만료되면 진행이 멈추고 스스로 복구 못 한다.

### 버전 관리와 업데이트 전략

**릴리스 채널** ⚠️

```json
// settings.json
{
  "autoUpdatesChannel": "stable",   // "latest"(기본) | "stable"
  "minimumVersion": "2.1.100"
}
```

- `latest` — 릴리스 즉시 반영 (기본)
- `stable` — 약 1주 지연, 심각한 회귀가 있는 릴리스는 건너뜀
- `/config` → **Auto-update channel**에서도 변경 가능
- Homebrew는 이 설정 대신 **cask 이름으로** 채널이 갈린다 (`claude-code` = stable, `claude-code@latest` = latest)

**버전 고정 4종 비교** ⚠️ — 헷갈리기 쉬움

| 키 | 하는 일 | 설정 위치 |
|---|---|---|
| `minimumVersion` | 이 아래로는 **업데이트하지 않음** (다운그레이드 방지) | 일반 설정 가능 |
| `requiredMinimumVersion` | 이 아래면 **아예 시작을 거부** | 관리 설정 전용 |
| `requiredMaximumVersion` | 이 위면 **시작 거부**. 업데이트도 이 천장을 지킴 | 관리 설정 전용 |
| `DISABLE_AUTOUPDATER` | 백그라운드 체크만 중단. `claude update`는 동작 | `env` 블록 |
| `DISABLE_UPDATES` | **모든 업데이트 경로 차단** (수동 포함) | `env` 블록 |

**수동 업데이트**

```bash
claude update              # 즉시 적용
claude install stable      # 채널 지정 재설치
claude install 2.1.89      # 특정 버전
curl -fsSL https://claude.ai/install.sh | bash -s stable   # 설치 시점에 채널 지정
```

**⚠️ 바이너리 무결성 검증** — 사내 배포 시 근거로 쓸 수 있는 내용

릴리스마다 플랫폼별 SHA256이 담긴 `manifest.json`을 배포하고, 그 매니페스트를 Anthropic GPG 키로 서명한다. 매니페스트 서명만 검증하면 그 안의 모든 바이너리가 전이적으로 검증된다.

- 서명 키 지문: `31DD DE24 DDFA B679 F42D 7BD2 BAA9 29FF 1A7E CACE`
- macOS: "Anthropic PBC" 서명 + Apple 공증 (`codesign --verify`)
- Windows: "Anthropic, PBC" 서명 (`Get-AuthenticodeSignature`)
- Linux: 개별 코드서명 없음 → 매니페스트 서명 또는 패키지 매니저 저장소 서명으로 검증
- 매니페스트 서명은 v2.1.89부터 제공

**업데이트 결과 확인**: `claude doctor` — 최근 업데이트 시도 결과를 보여준다.

### 대화형 모드 / 비대화형 모드

#### 대화형 모드

```bash
claude                         # 세션 시작
claude "explain this project"  # 초기 프롬프트와 함께 시작
claude -c                      # 현재 디렉토리 최근 대화 이어가기
claude -r "auth-refactor"      # 세션 ID 또는 이름으로 재개
```

**입력 접두사 4종**

| 접두사 | 동작 |
|---|---|
| `/` | 명령 또는 skill 실행 |
| `!` | **셸 모드** — Claude를 안 거치고 바로 실행, 명령과 출력이 컨텍스트에 들어감 |
| `@` | 파일 경로 자동완성 |
| `:` | ⚠️ 이모지 shortcode (v2.1.217+) |

⚠️ **셸 모드 동작 변경**: v2.1.186부터 `! npm test` 실행 시 **Claude가 출력에 자동으로 반응한다**. 두 번째 프롬프트 없이 실패 원인 설명을 받을 수 있다. 예전 동작(컨텍스트에만 추가)으로 되돌리려면 `respondToBashCommands: false`.

**꼭 알아야 할 단축키**

| 키 | 동작 |
|---|---|
| `Esc` | 현재 응답/도구 호출 중단. 큐에 메시지가 있으면 그걸 다음에 보냄 |
| `Esc` `Esc` | 입력이 비어 있으면 **rewind 메뉴**, 텍스트가 있으면 초안 정리(히스토리에 저장) |
| `Shift+Tab` | 권한 모드 순환 |
| `Ctrl+O` | 트랜스크립트 뷰어 토글 (도구 사용 상세, 타임스탬프, 모델) |
| `Ctrl+T` | Claude의 태스크 체크리스트 토글 |
| `Ctrl+B` | 실행 중인 Bash를 백그라운드로 (tmux는 두 번) |
| `Ctrl+R` | 히스토리 역방향 검색 |
| `Ctrl+G` | 외부 에디터로 프롬프트 편집 (plan mode에선 계획서 편집) |
| `Ctrl+S` | 프롬프트 stash / 복원 |
| `Alt+T` | 확장 사고 토글 (Fable 5는 항상 켜져 있어 무효) |

**메시지 큐잉** ⚠️
Claude가 작업 중일 때 Enter를 치면 인터럽트가 아니라 **큐에 쌓인다**.
- 일반 메시지 → 실행 중인 도구 호출이 끝나면 **같은 턴 안에서** 전달
- 명령·셸 명령 → 턴이 끝난 뒤 하나씩 실행
- `Up` (입력 첫 줄에서) → 큐를 회수해서 입력창으로 되돌림

#### 비대화형 모드 ⚠️ (예전 "headless mode"에서 개명)

```bash
claude -p "Find and fix the bug in auth.py" --allowedTools "Read,Edit,Bash"
cat build-error.txt | claude -p 'explain the root cause' > output.txt
claude -p "Summarize this project" --output-format json | jq -r '.result'
```

- stdin 파이프 지원 (**상한 10MB**)
- 성공 0, 실패 non-zero exit code → 스크립트에서 분기 가능
- 실행도 **재개 가능한 세션으로 저장된다** (`--no-session-persistence`로 끌 수 있음)
- 사용자 호출형 skill은 `-p`에서도 동작 (`/skill-name`을 프롬프트에 포함)
- `/login` 같은 터미널 전용 명령은 불가. `/model`, `/effort`, `/mcp`, `/config key=value` 등은 인자 형태로 가능 (v2.1.205+)

**출력 포맷**

| 값 | 결과 |
|---|---|
| `text` (기본) | 평문 |
| `json` | `result`, `session_id`, 메타데이터, `total_cost_usd` 포함 |
| `stream-json` | 줄 단위 JSON. 마지막 줄이 `result` 메시지 |

`--json-schema`로 JSON Schema를 주면 `structured_output` 필드에 스키마 준수 결과가 온다.

**⚠️ `--bare` 모드 — CI/스크립트의 새 기본** (문서상 "향후 `-p`의 기본값이 될 예정")

```bash
claude --bare -p "Summarize README.md" --allowedTools "Read"
```

훅, skills, 커스텀 명령, 서브에이전트, 플러그인, MCP 서버, auto memory, `CLAUDE.md`를 **전부 자동 탐색하지 않는다**. 어느 머신에서 돌려도 같은 결과가 필요한 CI에서 쓴다. Bash / 파일 읽기 / 파일 편집 도구만 있다.

> **보안상 중요**: `--bare` 없이 `claude -p`를 돌리면, **한 번도 신뢰한 적 없는 폴더에서도** 그 프로젝트 `.claude/settings.json`의 훅을 실행하고 `.mcp.json`의 서버에 연결한다. `-p` 세션은 워크스페이스 신뢰 다이얼로그도, 서버별 승인 프롬프트도 띄우지 않는다.

`--bare`에 컨텍스트를 주입하려면 플래그로: `--append-system-prompt`, `--settings`, `--mcp-config`, `--agents`, `--plugin-dir`.

### `.claude` 디렉토리 구조와 CLAUDE.md

#### 프로젝트 스코프

```
├── .worktreeinclude          # ⚠️ 워크트리에 복사할 gitignore된 파일 목록
└── .claude/
    ├── CLAUDE.md             # 루트 대신 여기 둬도 됨
    ├── settings.json         # 권한·훅·env·모델 (커밋)
    ├── settings.local.json   # 개인 오버라이드 (자동 gitignore)
    ├── rules/                # ⚠️ 주제별 지시, paths:로 조건부 로딩
    │   ├── testing.md
    │   └── api-design.md
    ├── skills/<name>/SKILL.md   # /name으로 호출, 보조 파일 번들 가능
    ├── commands/*.md            # 단일 파일 프롬프트 (skills로 대체 권장)
    ├── agents/*.md              # 서브에이전트 정의
    ├── workflows/*.js           # ⚠️ 동적 워크플로 스크립트
    ├── output-styles/*.md
    └── agent-memory/<agent>/    # ⚠️ 서브에이전트 영속 메모리
```

#### 글로벌 스코프

```
~/
├── .claude.json              # 앱 상태·OAuth·UI 토글·개인 MCP 서버 (직접 편집 X)
└── .claude/
    ├── CLAUDE.md             # 모든 프로젝트에 적용되는 개인 지시
    ├── settings.json         # 개인 기본 설정
    ├── keybindings.json      # ⚠️ 커스텀 단축키
    ├── themes/*.json         # ⚠️ 커스텀 테마
    ├── rules/  skills/  commands/  agents/  workflows/  output-styles/
    └── projects/<project>/
        ├── <session>.jsonl   # 대화 트랜스크립트 (평문!)
        └── memory/           # ⚠️ Auto memory
            ├── MEMORY.md
            └── debugging.md
```

> **⚠️ 자주 하는 실수**: `~/.claude.json`과 `~/.claude/settings.json`은 **완전히 다른 파일**이다.
> `permissions`, `hooks`, `env`는 `settings.json`에 넣어야 한다. `.claude.json`에 넣으면 조용히 무시된다.

#### CLAUDE.md — 위치와 로드 순서

| 스코프 | 위치 | 공유 대상 |
|---|---|---|
| **관리 정책** | mac `/Library/Application Support/ClaudeCode/CLAUDE.md`<br>Linux·WSL `/etc/claude-code/CLAUDE.md`<br>Win `C:\Program Files\ClaudeCode\CLAUDE.md` | 조직 전체 (개인이 제외 불가) |
| **사용자** | `~/.claude/CLAUDE.md` | 나 (모든 프로젝트) |
| **프로젝트** | `./CLAUDE.md` 또는 `./.claude/CLAUDE.md` | 팀 (버전관리) |
| **로컬** | `./CLAUDE.local.md` | 나 (해당 프로젝트, gitignore 필요) |

**로드 규칙 — 중요**

- 발견된 파일들은 **덮어쓰기가 아니라 전부 이어붙여진다(concatenate)**
- 순서는 **넓은 스코프 → 좁은 스코프**. 즉 실행 디렉토리에 가까운 지시가 마지막에 읽힘
- 각 디렉토리 안에서는 `CLAUDE.md` 다음 `CLAUDE.local.md`
- **상위 디렉토리들의 파일은 시작 시 로드**, **하위 디렉토리의 파일은 그 디렉토리 파일을 Read할 때 로드**
- 크기: 200줄 이하 목표. 4 MiB 넘으면 아예 스킵
- ⚠️ 블록 단위 HTML 주석(`<!-- ... -->`)은 컨텍스트 주입 전에 제거됨 → 사람용 메모를 토큰 소모 없이 남길 수 있다

**전달 방식** ⚠️
`CLAUDE.md`는 **시스템 프롬프트가 아니라, 시스템 프롬프트 뒤에 오는 사용자 메시지**로 전달된다. 그래서 엄격한 준수가 보장되지 않는다. 반드시 실행돼야 하는 규칙이면 **훅**으로, 절대 일어나면 안 되는 일이면 **권한 규칙**으로 써라.

**임포트**

```markdown
See @README for project overview and @package.json for npm commands.

- git workflow @docs/git-instructions.md
- 개인 설정 @~/.claude/my-project-instructions.md
```
최대 4단계까지 재귀. 코드 스팬·코드 블록 안의 `@`는 무시되므로, 임포트하지 않고 언급만 하려면 백틱으로 감싼다. **임포트한 파일도 시작 시 컨텍스트에 들어가므로 컨텍스트 절약 수단은 아니다.**

⚠️ 프로젝트 메모리 파일의 임포트가 작업 디렉토리 **밖**을 가리키면(예: 홈 디렉토리) 최초 1회 승인 다이얼로그가 뜬다. 남이 커밋한 파일로부터 보호하는 장치.

**⚠️ AGENTS.md 처리**
Claude Code는 `AGENTS.md`를 읽지 않는다. 이미 쓰고 있다면:

```markdown
<!-- CLAUDE.md -->
@AGENTS.md

## Claude Code
Use plan mode for changes under `src/billing/`.
```
또는 `ln -s AGENTS.md CLAUDE.md` (Windows는 심링크에 관리자 권한이 필요하니 임포트 방식 권장).

#### ⚠️ `.claude/rules/` — 조건부 로딩 (책에 없을 가능성 높음)

```markdown
---
paths:
  - "src/api/**/*.ts"
  - "src/**/*.{ts,tsx}"
---

# API Development Rules
- 모든 엔드포인트는 Zod 스키마로 입력 검증
- 응답 형태: { data: T } | { error: string }
```

- `paths:` **없으면** 시작 시 로드 (`.claude/CLAUDE.md`와 같은 우선순위)
- `paths:` **있으면** 매칭되는 파일을 Claude가 **읽을 때** 로드
- 하위 디렉토리 재귀 탐색 (`.claude/rules/frontend/react.md` 가능)
- 심링크 지원 → 여러 프로젝트에서 공용 룰셋 공유 가능
- `~/.claude/rules/`는 전 프로젝트 적용 (프로젝트 룰이 우선)
- **`CLAUDE.md`가 200줄에 가까워지면 rules로 쪼개기 시작할 때**

#### ⚠️ Auto memory — 완전히 새로운 기능

**Claude가 스스로 적는 메모.** 사용자가 쓰는 `CLAUDE.md`의 짝.

|  | CLAUDE.md | Auto memory |
|---|---|---|
| 작성자 | 사용자 | Claude |
| 내용 | 지시·규칙 | 학습·패턴 |
| 스코프 | 프로젝트/사용자/조직 | 저장소별 (모든 워크트리 공유) |
| 로딩 | 매 세션 전체 | 매 세션 `MEMORY.md` 앞 200줄 / 25KB |

저장 위치: `~/.claude/projects/<project>/memory/`

기록하는 4종류 (`type` 프론트매터):
- `user` — 역할, 전문 분야, 작업 선호
- `feedback` — 사용자가 준 교정, 확인된 접근법
- `project` — 진행 중인 작업, 마감, 코드/git에서 유추 불가능한 결정
- `reference` — 프로젝트 밖 정보 위치 (이슈 트래커, 대시보드)

**코드베이스에서 유추 가능한 것(아키텍처, 파일 경로, 디버깅 픽스)과 `CLAUDE.md`가 이미 말한 것은 저장하지 않는다.**

- 기본 켜짐. `/memory`의 토글 또는 `autoMemoryEnabled: false`, 또는 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`
- **머신 로컬**. 다른 머신·클라우드 환경과 공유 안 됨
- 30일 보존 스윕에서 **제외**됨 (직접 지우기 전까지 유지)
- `MEMORY.md`는 인덱스. 주제 파일(`debugging.md` 등)은 필요할 때 온디맨드로 읽음
- 세션 중 "Saved 2 memories" / "Recalled 2 memories" 메시지가 이 동작
- 평범한 마크다운이라 언제든 열어서 편집·삭제 가능

#### ⚠️ 애플리케이션 데이터와 평문 저장 (보안 논의거리)

`~/.claude/` 아래에 **암호화되지 않은 평문**으로 쌓인다.

- `projects/<project>/<session>.jsonl` — 모든 메시지·도구 호출·도구 결과 전문
- `history.jsonl` — 지금까지 친 **모든 프롬프트** (타임스탬프 + 프로젝트 경로)
- `file-history/<session>/` — 편집 전 파일 스냅샷 (체크포인트 복원용)
- `paste-cache/`, `image-cache/`, `shell-snapshots/`, `debug/` 등

> Claude가 `.env`를 읽거나 명령이 자격증명을 출력하면 **그 값이 트랜스크립트에 그대로 기록된다.** OS 파일 권한이 유일한 보호 수단.

완화 방법:
- `cleanupPeriodDays` 축소 (기본 30일, 최소 1)
- `CLAUDE_CODE_SKIP_PROMPT_HISTORY` — 트랜스크립트·프롬프트 히스토리 기록 안 함
- 권한 규칙으로 자격증명 파일 읽기 거부 (`"deny": ["Read(./.env)", "Read(./.env.*)"]`)
- ⚠️ `claude project purge <path>` — 프로젝트 하나의 로컬 상태 전부 삭제 (`--dry-run`으로 미리보기)

### 필수 슬래시 명령어

> ⚠️ **용어 정정**: 공식 제품 용어에서 "slash"가 빠져 그냥 **Commands**다. 그리고 **custom commands → skills**로 명칭이 바뀌었다. `.claude/commands/*.md`는 계속 동작하지만, 새로 만들 땐 skills 권장.

#### 워크플로 흐름으로 묶어보기

**저장소 첫 세션**
```
/init         → CLAUDE.md 생성 (코드베이스 분석해서 빌드·테스트 명령, 컨벤션 추출)
/memory       → 생성된 CLAUDE.md 다듬기, auto memory 토글
/mcp          → MCP 서버 설정
/permissions  → 승인 규칙 설정
```

**작업 중**
```
/plan [설명]  → plan mode 진입 (큰 변경 전)
/model /effort → 모델·추론 강도 조정
/context      → 컨텍스트 사용량 확인
/compact [초점] → 요약해서 공간 확보
/btw <질문>   → ⚠️ 히스토리에 안 남는 사이드 질문
```

**출하 전**
```
/diff             → 변경 확인 (인터랙티브 뷰어, 턴별 diff)
/code-review      → ⚠️ 현재 diff 리뷰. --fix로 적용, PR 번호 지정 가능. 별칭 /review
/security-review  → 보안 취약점 검사
```

**세션 사이**
```
/clear [이름]  → 컨텍스트 비우고 새 대화 (이전 대화는 /resume으로 복귀)
/resume        → 이전 대화 재개 (별칭 /continue)
/branch [이름] → ⚠️ 현재 대화를 분기해서 다른 방향 시도
/fork [프롬프트] → ⚠️ 백그라운드 세션으로 복사 (여긴 계속 작업)
```

**문제 생겼을 때**
```
/rewind    → 코드·대화 되감기 또는 부분 요약 (별칭 /checkpoint, /undo)
/doctor    → ⚠️ 설정 점검 + 수정 제안 (별칭 /checkup)
/debug     → 디버그 로깅 켜고 로그 읽어 진단
/feedback  → 버그 리포트
```

#### 기본 명령 표

| 명령 | 하는 일 |
|---|---|
| `/help` | 도움말과 사용 가능한 명령 |
| `/clear` | 컨텍스트 비우고 새 대화. 별칭 `/reset` `/new` |
| `/exit` | 종료. 별칭 `/quit`. 백그라운드 세션에 attach 중이면 detach만 |
| `/compact [지시]` | 대화 요약해서 공간 확보 |
| `/context [all]` | 컨텍스트 사용량 시각화 + 최적화 제안 |
| `/status` | 활성 설정 소스, 로그인 상태, 관리 설정 적용 여부 |
| `/config [key=value]` | 설정 UI. ⚠️ v2.1.181+ `key=value` 직접 지정 가능 |
| `/model [모델]` | 모델 전환 + 기본값 저장. `s` 키를 누르면 이번 세션만 |
| `/permissions` | allow/ask/deny 규칙 관리 |
| `/memory` | CLAUDE.md 편집, auto memory 토글·조회 |
| `/init` | CLAUDE.md 생성 |
| `/mcp` | MCP 서버 연결 관리·OAuth |
| `/hooks` | 등록된 훅 확인 |
| `/usage` | 사용량·비용. 별칭 `/cost` |
| `/export [파일]` | 대화를 평문으로 내보내기 |
| `/copy [N]` | 마지막(또는 N번째 최근) 응답 복사 |
| `/add-dir <경로>` | 세션에 작업 디렉토리 추가 |
| `/rename [이름]` | 세션 이름 지정 (프롬프트 바에 표시) |
| `/release-notes` | 변경 로그를 버전 피커로 확인 |
| `/tasks` | 실행 중인 셸·서브에이전트 (Ctrl+T의 체크리스트와 다름) |

⚠️ 명령을 응답 중에 보내면 큐에 쌓였다가 턴 종료 후 실행된다. 단 `/status`, `/tasks`, `/usage`는 즉시 실행. v2.1.234부터 `/theme` `/help` 같은 다이얼로그도 즉시 열린다.

⚠️ **번들 skill vs 내장 명령**: `/batch` `/code-review` `/debug` `/doctor` `/loop` `/run` 등은 **번들 skill**이다 — 고정 로직이 아니라 Claude에게 건네지는 상세 프롬프트. 그래서 에이전트를 띄우고 파일을 읽고 코드베이스에 적응할 수 있다.

⚠️ **명령 체이닝** (v2.1.199+): `/skill-a /skill-b do XYZ` 형태로 최대 6개 skill을 연달아 호출하고 뒤의 텍스트를 전부에 인자로 전달할 수 있다.

### 다양한 실행 플래그

#### 자주 쓰는 것

| 플래그 | 설명 |
|---|---|
| `-p`, `--print` | 비대화형 실행 후 종료 |
| `-c`, `--continue` | 현재 디렉토리 최근 대화 재개 |
| `-r`, `--resume [세션]` | ID/이름으로 재개, 인자 없으면 피커 |
| `--model <모델>` | `sonnet` `opus` `haiku` `fable` 또는 전체 모델명 |
| `--permission-mode <모드>` | `default`(=`manual`) `acceptEdits` `plan` `auto` `dontAsk` `bypassPermissions` |
| `--add-dir <경로...>` | 추가 작업 디렉토리. **파일 접근만 주고 `.claude/` 설정은 안 읽음** |
| `--allowedTools "Read,Edit,Bash(git diff *)"` | 프롬프트 없이 실행할 도구 |
| `--disallowedTools "mcp__*"` | 거부 규칙 |
| `--tools "Bash,Edit,Read"` | 사용 가능한 내장 도구 자체를 제한 |
| `--output-format text\|json\|stream-json` | 출력 형식 (print 모드) |
| `-n`, `--name <이름>` | 세션 이름 지정 |
| `--verbose` | 턴별 전체 출력 |

#### ⚠️ 알아두면 좋은 신규/유용 플래그

| 플래그 | 설명 |
|---|---|
| `--bare` | 최소 모드. 훅·skill·MCP·CLAUDE.md 자동탐색 스킵. **CI 권장** |
| `--safe-mode` | 모든 커스터마이징 끄고 시작. **설정 문제 격리용**. `--bare`와 달리 권한·모델·내장 도구는 정상 |
| `-w`, `--worktree [이름]` | 격리된 git worktree(`<repo>/.claude/worktrees/<name>`)에서 시작. PR 번호(`#123`)로 브랜치 가능 |
| `--fork-session` | 재개 시 원본은 두고 새 세션 ID로 복사 |
| `--effort low\|medium\|high\|xhigh\|max\|ultracode` | 추론 강도 |
| `--autocompact 500k` | 이번 세션의 자동 압축 지점 (v2.1.221+) |
| `--settings <파일\|JSON>` | 이번 세션만 설정 오버라이드 |
| `--setting-sources user,project,local` | 읽을 설정 소스 제한 |
| `--append-system-prompt "..."` | 기본 시스템 프롬프트 뒤에 추가 |
| `--system-prompt "..."` | 시스템 프롬프트 **전체 교체** (도구 가이드·안전 지시까지 날아감) |
| `--agents '{"reviewer":{...}}'` | JSON으로 서브에이전트 즉석 정의 |
| `--mcp-config ./mcp.json` | MCP 서버를 파일/문자열로 로드 |
| `--strict-mcp-config` | `--mcp-config`의 서버만 사용 |
| `--max-turns 3` | 에이전틱 턴 수 제한 (print 모드) |
| `--max-budget-usd 5.00` | 지출 상한 (print 모드, 서브에이전트 포함) |
| `--json-schema '{...}'` | 구조화 출력 스키마 |
| `--cloud "task"` | 클라우드 세션 생성/타겟 |
| `--teleport` | 웹 세션을 로컬 터미널로 가져오기 |
| `--bg`, `--background` | 백그라운드 에이전트로 시작 (`-p`와 병용 불가) |
| `--debug='mcp,startup'` | 카테고리 필터 디버그. **`=` 형태여야 필터가 붙음** |
| `--chrome` / `--no-chrome` | Chrome 브라우저 통합 |

**⚠️ 시스템 프롬프트 플래그 4종**

| 플래그 | 동작 |
|---|---|
| `--system-prompt` | 전체 교체 |
| `--system-prompt-file` | 파일 내용으로 전체 교체 |
| `--append-system-prompt` | 기본 프롬프트에 추가 |
| `--append-system-prompt-file` | 파일 내용을 추가 |

교체 계열 2개는 상호 배타. 추가 계열은 교체 계열과 병용 가능.
**판단 기준**: Claude Code의 기본 정체성(코딩 어시스턴트)이 여전히 맞으면 append, 아예 다른 역할(사람이 안 보는 파이프라인의 비코딩 에이전트)이면 replace. Replace하면 도구 가이드와 안전 지시까지 다 날아가므로 필요한 걸 직접 채워야 한다.

> `claude --help`가 모든 플래그를 나열하지는 않는다. `--help`에 없다고 없는 플래그가 아니다.

#### 주요 CLI 서브커맨드

```bash
claude doctor              # 세션 없이 설치·설정 진단 (읽기 전용)
claude update              # 최신 버전으로
claude install [버전]      # 네이티브 바이너리 설치/재설치
claude mcp add ...         # MCP 서버 설정
claude mcp login <이름>    # ⚠️ /mcp 패널 없이 OAuth 플로우
claude setup-token         # CI용 장기 토큰
claude auth login|logout|status   # ⚠️ 인증 서브커맨드 (status는 JSON, --text로 사람용)
claude agents              # ⚠️ agent view — 백그라운드 세션 모니터링·디스패치
claude project purge [경로] # ⚠️ 프로젝트 로컬 상태 삭제
claude plugin install ...  # 플러그인 관리
```

오타를 내면 가장 가까운 명령을 제안하고 세션을 시작하지 않는다 (`claude udpate` → `Did you mean claude update?`).

- 설치 건강도: 중복/잔여 설치, `PATH` 문제, 파싱 안 되는 설정 파일
- 컨텍스트 비용 대비 안 쓰는 skill·MCP 서버·플러그인 탐지
- 느린 훅 플래그
- 릴리스 채널 기준 신버전 확인
- ⚠️ **커밋된 `CLAUDE.md` 다이어트 제안** (v2.1.206+) — 코드베이스에서 유추 가능한 내용(디렉토리 구조, 의존성 목록, 아키텍처 개요)을 잘라내고, 함정·근거·기본값과 다른 컨벤션은 남긴다
- auto mode를 기본으로 할지, 자주 거부되는 읽기 전용 명령을 미리 승인할지 제안

#### 깨끗한 환경에서 격리하기 (2단계) ⚠️

```bash
# 1단계 — 커스터마이징 전부 끄고 시작
claude --safe-mode
# CLAUDE.md, skills, plugins, hooks, MCP, 커스텀 명령·에이전트,
# output style, workflow, 테마, 키바인딩, LSP, auto memory 전부 미로딩.
# 인증·모델 선택·내장 도구·권한은 정상 동작.

cd /tmp && CLAUDE_CONFIG_DIR=/tmp/claude-clean claude
```

safe-mode에서 문제가 사라지면 → 커스터마이징 중 하나가 원인. 위 진단 명령으로 좁혀 들어간다.
safe-mode에서도 남으면 → 사용자·프로젝트 설정 밖의 문제. `/status`로 관리 설정 확인 → 환경변수 확인.

#### ⚠️ 흔한 원인 표 (버그로 의심하기 전에 볼 것)

| 증상 | 원인 | 해결 |
|---|---|---|
| 훅이 안 걸림 | `matcher`가 JSON 배열 | 문자열로. `"Edit\|Write"` |
| 훅이 안 걸림 | matcher가 소문자 (`"bash"`) | **대소문자 구분함.** `Bash` `Edit` `Write` `Read` |
| 훅이 안 걸림 | 훅을 별도 파일에 정의 | 프로젝트/사용자 훅은 `settings.json`의 `"hooks"` 키 아래에만 (별도 훅 파일은 플러그인 전용) |
| 전역 권한·훅·env가 무시됨 | `~/.claude.json`에 넣음 | `~/.claude/settings.json`으로 |
| `settings.json` 값이 무시됨 | 같은 키가 `settings.local.json`에 있음 | 우선순위 확인 |
| skill이 `/skills`에 안 뜸 | `.claude/skills/name.md`로 만듦 | **폴더 + `SKILL.md`**: `.claude/skills/name/SKILL.md` |
| skill이 뜨는데 Claude가 안 씀 | `disable-model-invocation: true` 또는 description 불일치 | `/skills`의 "user-only" 뱃지 확인 |
| 하위 디렉토리 `CLAUDE.md`가 무시됨 | 온디맨드 로딩 | 그 디렉토리 파일을 **Read**해야 로드됨. 쓰기·생성으로는 안 됨 |
| 서브에이전트가 `CLAUDE.md` 무시 | 내장 Explore/Plan 에이전트는 스킵함 | 위임 프롬프트에 다시 쓰거나, 커스텀 에이전트 본문에 넣기 |
| `.mcp.json` 서버가 안 뜸 | `.claude/` 안에 넣었거나 Desktop 포맷 사용 | **저장소 루트**에 `.mcp.json` |
| `settings.json`의 `mcpServers`가 안 먹힘 | `settings.json`은 이 키를 안 읽음 | `.mcp.json` 또는 `claude mcp add --scope user` |
| MCP 서버가 특정 디렉토리에서 실패 | `command`/`args`의 상대 경로 | 로컬 스크립트는 절대 경로로 |
| `Bash(rm *)` deny가 `/bin/rm`을 못 막음 | 접두사 규칙은 **문자열 매칭**이지 실행 파일 매칭이 아님 | 변형별 패턴 추가, 또는 PreToolUse 훅 / 샌드박스 |

#### 설정 파일이 깨졌을 때

- **Settings Error** — JSON 문법 오류나 스키마 거부. 대화형 세션 시작 시 다이얼로그: Claude 도움으로 수정 / 종료 / 무시하고 계속
- **Settings Warning** — 개별 항목만 실패. 그 값만 건너뛰고 나머지는 유효
- **Configuration error** — `~/.claude.json` 파싱 불가. `~/.claude/backups/.claude.json.corrupted.<ts>`로 복사되고 복구 여부를 물음. 최근 5개 백업 보관
- ⚠️ **`-p` 실행은 다이얼로그가 안 뜬다.** 깨진 파일/값을 조용히 건너뛰고 계속하므로, `-p` 실행 후엔 `claude doctor`로 뭐가 버려졌는지 확인해야 한다

### 체크포인트와 되감기 시스템

#### 동작 방식

- **사용자가 프롬프트를 보낼 때마다 체크포인트 생성**
- 편집 전 파일 스냅샷을 뜬다 (`~/.claude/file-history/<session>/`)
- 세션당 **최근 100개** 체크포인트의 스냅샷 유지
- **대화와 함께 저장**된다 → 터미널을 닫고 나중에 `--resume`해도 `/rewind` 가능
- 30일(`cleanupPeriodDays`) 후 세션과 함께 삭제

#### 되감기 메뉴

`/rewind` 또는 **입력창이 빈 상태에서 `Esc` 두 번**. (입력에 텍스트가 있으면 초안을 지우고 히스토리에 저장 → `Up`으로 회수 가능)

세션 중 보낸 프롬프트 목록이 뜨고, 지점을 고른 뒤 액션 선택:

| 액션 | 결과 |
|---|---|
| **Restore code and conversation** | 코드와 대화 모두 되돌림 |
| **Restore conversation** | 대화만. 코드는 현재 상태 유지 |
| **Restore code** | 파일 변경만 되돌림. 대화는 유지 |
| **Summarize from here** ⚠️ | 이 지점 **이후**를 요약으로 압축 (앞은 온전히 유지) |
| **Summarize up to here** ⚠️ | 이 지점 **이전**을 요약으로 압축 (뒤는 온전히 유지) |
| Never mind | 취소 |

코드 복원 두 옵션은 **해당 체크포인트에 추적된 파일 변경이 있을 때만** 나타난다.

⚠️ 요약 옵션은 **타겟팅된 `/compact`**로 생각하면 된다. 화살표로 요약 옵션에 커서를 두고 `add context (optional)` 행에 지시를 타이핑하면 요약의 초점을 지정할 수 있다. 숫자 키로 바로 선택하면 지시 없이 즉시 요약.

⚠️ **`/clear` 이후의 되감기** (v2.1.191+)
같은 Claude Code 프로세스에서 `/clear`를 했다면, rewind 메뉴 맨 위에 `/resume <session-id> (previous session)` 항목이 뜬다. 실수로 clear했을 때 되돌리는 길.

#### ⚠️ 한계 5가지 (이게 시험에 나올 부분)

1. **Bash 명령으로 바뀐 파일은 추적 안 됨** — `rm`, `mv`, `cp`로 바꾼 건 되돌릴 수 없다. Claude의 **파일 편집 도구**로 한 변경만 추적
2. **서브에이전트 편집은 복원 안 됨** — 예외: `context: fork` skill을 **포그라운드**로 실행한 경우엔 복원됨. 그 외(백그라운드 fork, `/code-review --fix` 등)는 git으로 되돌려야 함
3. **외부 변경 미추적** — 사용자가 직접 수정한 파일, 다른 동시 세션의 편집
4. **심링크·하드링크 복원 안 함** ⚠️ — 복원 시 건너뛰고 `Restored the code, but skipped N files` 경고. dotfile 매니저가 심링크한 설정 파일, pnpm이 하드링크한 파일이 여기 해당. 어떤 경로가 스킵됐는지는 `/debug` 켜고 복원한 뒤 `~/.claude/debug/<session-id>.txt`에서 확인
5. **버전관리 대체가 아니다** — 세션 단위 빠른 복구용

#### 활용 관점

체크포인트가 있으면 **계획을 완벽히 세우는 대신 과감히 시도해보고 안 되면 되감는** 방식이 가능해진다. 이게 best practices에서 밀고 있는 작업 스타일이다.

### settings.json 에 대해서

#### 파일 4종 + 관리 설정

| 스코프 | 파일 | 영향 범위 | 용도 |
|---|---|---|---|
| **User** | `~/.claude/settings.json` | 이 머신의 모든 프로젝트, 나만 | 테마, 에디터 모드, 기본 모델, 개인 권한 규칙 |
| **Shared project** | `.claude/settings.json` | 이 폴더에서 시작하는 모두 (커밋 시 팀 공유) | 팀 권한, 훅, 플러그인, 프로젝트 env |
| **Project local** | `.claude/settings.local.json` | 이 프로젝트, 나만 (자동 gitignore) | 개인 오버라이드, 공유 전 테스트 |
| **Managed** | `managed-settings.json` 외 | 조직이 배포한 대상 전체 | 보안 정책, 컴플라이언스 |

> **설치해도 설정 파일이 자동 생성되지 않는다.** `/config`에서 옵션을 바꾸면 `~/.claude/settings.json`이, 권한 프롬프트에서 "Yes, and don't ask again"을 고르면 `.claude/settings.local.json`이 만들어진다.

#### 우선순위 (높은 순)

```
1. 관리 설정 (managed-settings.json / MDM / claude.ai 콘솔)
2. 커맨드라인 (--settings)
3. 프로젝트 로컬 (.claude/settings.local.json)
4. 공유 프로젝트 (.claude/settings.json)
5. 사용자 (~/.claude/settings.json)
```

**⚠️ 배열은 병합, 스칼라는 오버라이드.**
`permissions.allow` 같은 리스트는 모든 스코프에서 합쳐진다. `model` 같은 단일 값은 가장 높은 레이어의 값을 쓴다.

병합 규칙 예외 3가지:
- `fallbackModel` — 순서가 의미를 가지는 체인이라 통째로 가져옴
- `modelPicker` — 두 소스의 행을 병합하지 않음 (v2.1.242+)
- `availableModels` — 최상위 관리 소스가 정의하면 그 리스트를 그대로 적용

**환경변수는 이 스택의 레이어가 아니다.** 키-변수 쌍마다 별도로 결정된다. 예: `ANTHROPIC_MODEL`은 어느 파일의 `model`보다 우선하지만, `ANTHROPIC_DEFAULT_MODEL`은 파일에 `model`이 없을 때만 적용.

#### 설정 변경 3가지 경로

```bash
/config                       # UI 메뉴 (일부 개인 옵션만)
/config verbose=true          # ⚠️ key=value 직접 지정
/config theme=dark            # ⚠️ 명명된 shorthand 키 (v2.1.182+)

# 파일 직접 편집
# 이번 세션만
claude --settings '{"model": "claude-opus-4-8"}'
```

#### ⚠️ 변경이 언제 반영되나 — 자주 헷갈리는 부분

**대부분은 핫 리로드된다.** 설정 파일을 감시하다가 바뀌면 실행 중인 세션에 적용한다 (`permissions`, `hooks`, `apiKeyHelper` 포함). 재시작 불필요.

세션 시작 시 한 번만 읽는 예외:

| 키 | 대신 |
|---|---|
| `model` | `/model`로 세션 중 전환 (모델마다 프롬프트 캐시가 달라 첫 요청은 캐시 미스) |
| `effortLevel` | `/effort` |
| `outputStyle` | 시스템 프롬프트의 일부라 `/clear` 또는 재시작 후 적용 |

#### 실전 예시

```json
// ~/.claude/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "allow": ["Bash(npm run lint)", "Bash(npm run test *)"],
    "deny": ["Read(./.env)", "Read(./.env.*)"]
  }
}
```

`$schema`를 넣으면 VS Code 등에서 자동완성과 인라인 검증이 된다. 다만 스키마가 최신 CLI보다 늦을 수 있어 새 키에 경고가 떠도 잘못된 설정은 아니다.

```json
// .claude/settings.json — 팀 공유
{
  "permissions": {
    "allow": ["Bash(npm test *)", "Bash(npm run *)"],
    "deny": ["Bash(rm -rf *)"]
  },
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write"
      }]
    }]
  }
}
```

> **설정 파일은 엄격한 JSON이다.** `//` 주석이나 trailing comma는 문법 오류다.

#### 주요 키 카테고리 (settings-reference)

| 카테고리 | 예시 키 |
|---|---|
| 모델·응답 | `model` `fallbackModel` `availableModels` `effortLevel` `outputStyle` `fastMode` `promptCacheTtl` |
| 권한 | `permissions.allow/ask/deny` `permissions.defaultMode` `permissions.additionalDirectories` `autoMode` |
| 샌드박스 | `sandbox.enabled` `sandbox.network.allowedDomains` `sandbox.filesystem.*` `sandbox.credentials.*` |
| 메모리·컨텍스트 | `autoCompactEnabled` `autoCompactWindow` `autoMemoryEnabled` `claudeMd` `claudeMdExcludes` `fileCheckpointingEnabled` |
| 인터페이스 | `theme` `editorMode` `statusLine` `verbose` `viewMode` `keybindingFlavor` `spellcheck` |
| Git·귀속 | `includeCoAuthoredBy` `attribution.commit` `attribution.pr` `prUrlTemplate` |
| 훅·자동화 | `hooks` `disableAllHooks` `allowManagedHooksOnly` `allowedHttpHookUrls` |
| 플러그인·skill | `enabledPlugins` `extraKnownMarketplaces` `disableBundledSkills` `skillOverrides` |
| MCP | `allowedMcpServers` `deniedMcpServers` `enableAllProjectMcpServers` |
| 업데이트 | `autoUpdatesChannel` `minimumVersion` `requiredMinimumVersion` `requiredMaximumVersion` |
| 프라이버시 | `cleanupPeriodDays` `feedbackSurveyRate` |

⚠️ **저장소 파일에서는 안 먹히는 키가 있다.** settings-reference의 Scope 열이 `User, local, or managed` / `User or managed` / `Managed` / `Global config`인 키는 공유 `.claude/settings.json`에서 적용되지 않는다. 팀에 배포했는데 안 먹으면 여기를 먼저 보라.

⚠️ **신뢰(trust)를 기다리는 키도 있다.** `permissions.allow`, `permissions.additionalDirectories`, `extraKnownMarketplaces`, 대부분의 `env` 값은 각자가 **폴더를 신뢰한 후에만** 적용된다. `deny`와 `ask` 규칙은 즉시 적용된다.

## 1-4 프로젝트로 특징 이해하기

### 프로젝트 컨텍스트의 이해

#### 세션은 디렉토리에 묶인다

- `claude`를 실행한 디렉토리가 그 세션의 정체성
- **각 세션은 독립적인 컨텍스트 윈도우로 시작한다.** 이전 세션 히스토리를 안 가져옴
- 세션 간 지식 전달은 **`CLAUDE.md`**(사용자 작성)와 **auto memory**(Claude 작성) 두 갈래
- 트랜스크립트는 `~/.claude/projects/<project>/<session>.jsonl`

#### git 브랜치와의 관계 ⚠️

- Claude는 **현재 브랜치의 파일**을 본다
- 브랜치를 바꾸면 보는 파일이 바뀌지만 **대화 히스토리는 그대로**다. 브랜치 전환 후에도 논의한 내용을 기억한다
- `/resume` 피커는 기본적으로 현재 워크트리의 세션을 보여주고, 단축키로 다른 워크트리·프로젝트까지 확장
- 병렬 작업은 **git worktree** (`claude -w feature-auth`)로

#### 세션 재개 vs 분기 ⚠️

| 방법 | 결과 |
|---|---|
| `claude -c` / `claude -r` / `/resume` | **같은 세션 ID**에 새 메시지를 이어붙임 |
| `--fork-session` / `/branch` | 히스토리를 **새 세션 ID로 복사**. 원본은 그대로 |
| `/fork` | 백그라운드 세션으로 복사. 현재 세션은 계속 작업 |

#### 프로젝트 신뢰(trust) ⚠️

디렉토리를 처음 열면 신뢰 다이얼로그가 뜬다. 승인은 프로젝트 디렉토리별로 저장된다(홈 디렉토리는 예외 — 세션 단위로만 유지되어 매번 물음).

신뢰하기 전까지는 저장소가 제공하는 일부 콘텐츠를 보류한다: `.claude/settings.json`의 프로젝트 allow 규칙, 마켓플레이스 등. **`-p` 세션은 다이얼로그 없이 진행하므로 별도 주의가 필요하다** (앞서 언급).

#### 컨텍스트 확인 루틴

```bash
/init                # CLAUDE.md 생성 또는 개선 제안
/context             # Memory files 항목에서 어떤 파일이 로드됐는지 확인
/memory              # 메모리 파일 열기·편집
```

`/context`의 **Memory files** 목록에 파일이 없으면 Claude는 그 파일을 못 보고 있는 것이다. 위치 문제인지 확인.

`--add-dir`로 추가한 디렉토리는 **파일 접근만** 준다. 그 디렉토리의 `.claude/` 설정과 `CLAUDE.md`는 기본적으로 로드되지 않는다. 메모리 파일까지 읽으려면:
```bash
CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1 claude --add-dir ../shared-config
```

### 간단한 프로그램 작성

#### 첫 세션 흐름

```
what does this project do?          # 코드베이스 파악
what technologies does this use?
where is the main entry point?

add a hello world function to the main file    # 첫 변경
```

**⚠️ 권한 모드 기본값이 바뀌었다.** 첫 세션에서는 모든 변경에 승인을 묻는다. 그 이후부터는 **Pro / Max / Team 플랜의 대화형 터미널·VS Code 세션은 `auto` 모드로 시작**한다.

| 모드 | 동작 |
|---|---|
| **Auto** ⚠️ | 별도 분류기 모델이 대부분의 행동을 백그라운드에서 검토하고 **위험한 것만 차단**한다. 프롬프트가 안 뜸. Pro/Max/Team 기본 시작 모드 |
| **Manual** (`default`) | 파일 편집과 셸 명령 전에 물음. 다른 플랜의 기본 |
| **Accept edits** | 파일 편집과 `mkdir`/`mv` 같은 흔한 파일시스템 명령은 안 물음 |
| **Plan** | 탐색과 계획만. 소스 파일 편집 안 함 |
| **dontAsk** | allow 규칙과 읽기 전용 명령 집합에 없으면 전부 거부. 잠긴 CI용 |
| **bypassPermissions** | 모든 검사 스킵 |

`Shift+Tab`으로 순환. auto 모드에서는 첫 번째 누름이 `default`로 간다.

⚠️ auto 모드 분류기는 **도구 결과가 제거된 상태로** 행동을 검토한다. 그래서 파일이나 웹 페이지에 심어진 적대적 텍스트가 분류기를 직접 조종할 수 없다. 차단 대상: 범위 확대(scope escalation), 신뢰되지 않은 인프라, 프롬프트 인젝션.

#### 권장 4단계 워크플로 (explore → plan → code → commit)

```
1. Explore   Shift+Tab으로 plan mode 진입 (또는 claude --permission-mode plan)
             "read /src/auth and understand how we handle sessions and login"

2. Plan      "I want to add Google OAuth. What files need to change? Create a plan."
             Ctrl+G로 계획서를 에디터에서 직접 수정 가능

3. Implement 계획 승인 또는 Shift+Tab으로 빠져나온 뒤
             "implement the OAuth flow from your plan. write tests for the
              callback handler, run the test suite and fix any failures."

4. Commit    "commit with a descriptive message and open a PR"
```

**⚠️ plan mode가 항상 옳은 건 아니다.** 오버헤드가 있다. 오타 수정, 로그 한 줄 추가, 변수명 변경처럼 범위가 명확하고 작으면 바로 시키는 게 낫다.
판단 기준: **"diff를 한 문장으로 설명할 수 있으면 계획을 건너뛴다."**
계획이 값어치를 하는 경우 — 접근 방식이 불확실할 때, 여러 파일을 건드릴 때, 수정 대상 코드에 익숙하지 않을 때.

#### 프롬프트를 구체적으로

| 나쁜 예 | 좋은 예 |
|---|---|
| "add tests for foo.py" | "write a test for foo.py covering the edge case where the user is logged out. avoid mocks." |
| "fix the login bug" | "users report that login fails after session timeout. check the auth flow in src/auth/, especially token refresh. write a failing test that reproduces the issue, then fix it" |
| "add a calendar widget" | "look at how existing widgets are implemented on the home page. HotDogWidget.php is a good example. follow the pattern to implement..." |
| "the build is failing" | "the build fails with this error: [붙여넣기]. fix it and verify the build succeeds. address the root cause, don't suppress the error" |

단, **탐색 단계에서는 모호한 프롬프트가 유용하다.** "what would you improve in this file?" 같은 건 물어볼 생각조차 못 한 것을 끌어내 준다.

#### ⚠️ 큰 기능은 Claude에게 인터뷰를 시켜라

```
I want to build [간단한 설명]. Interview me in detail using the AskUserQuestion tool.

Ask about technical implementation, UI/UX, edge cases, concerns, and tradeoffs.
Don't ask obvious questions, dig into the hard parts I might not have considered.

Keep interviewing until we've covered everything, then write a complete spec to SPEC.md.
```

스펙이 완성되면 **새 세션을 시작해서** 실행한다. 새 세션은 구현에만 집중된 깨끗한 컨텍스트를 갖고, 참조할 문서가 손에 있다.
좋은 스펙의 조건: 관련 파일과 인터페이스를 명시, 범위 밖인 것을 명시, **기능이 동작함을 증명하는 end-to-end 검증 단계로 끝맺기**.

### 파일 읽기와 쓰기 패턴

#### Read

- 절대 경로를 넘긴다. 결과에 **줄 번호가 붙어서** 온다
- 파일 전체가 토큰 한도를 넘으면 첫 페이지 + **`PARTIAL view` 안내**가 오고, `offset`/`limit`으로 더 읽는다
- **이미지**(PNG/JPG 등) — 원시 바이트가 아니라 **Claude가 볼 수 있는 시각 콘텐츠**로 반환. 큰 이미지는 리사이즈·재압축됨. 픽셀 단위 디테일이 필요하면 ImageMagick으로 관심 영역을 잘라서 주는 게 낫다
- **PDF** — 10페이지 이하는 통째로, 넘으면 `pages: "1-5"` 형태로 한 번에 20페이지까지
- **Jupyter 노트북**(`.ipynb`) — 모든 셀과 출력 포함
- **디렉토리는 못 읽는다.** `ls` 같은 셸 명령으로

#### Edit — 정확한 문자열 치환

정규식도, 퍼지 매칭도 아니다. 세 가지 검사를 통과해야 한다.

1. **Read-before-edit** — 현재 대화에서 그 파일을 읽었어야 한다
   - ⚠️ v2.1.208+: 최신 모델은 (읽기에 권한 프롬프트가 필요 없고 Read 도구가 있으면) 안 읽은 파일도 편집할 수 있다. Opus 4.6 / Haiku 4.5 이하는 항상 읽어야 함
   - ⚠️ `cat`, `head`, `tail`, `sed -n 'X,Yp'`, `grep`, `rg` 등으로 **단일 파일을 파이프·리다이렉트 없이** 본 것도 이 요건을 충족한다
2. **Match** — `old_string`이 파일에 **글자 그대로** 있어야 한다. 공백 하나, 들여쓰기 하나만 달라도 실패
3. **Uniqueness** — `old_string`이 **정확히 한 번만** 나타나야 한다. 여러 번 나오면 주변 컨텍스트를 더 붙여 유일하게 만들거나 `replace_all: true`

⚠️ `Edit(...)` allow 규칙은 같은 경로의 **읽기 권한도 함께 준다** (별도 `Read(...)` 규칙 불필요).
⚠️ `Read(...)` deny 규칙은 같은 경로의 **Edit·Write도 막는다** (새 파일 생성 포함).

#### Write — 전체 덮어쓰기

append도 merge도 아니다. 기존 파일의 부분 수정은 Edit을 쓴다.
기존 파일 덮어쓰기 전 읽기 요건은 Edit과 같은 규칙. 새 파일은 해당 없음.

#### Glob vs Grep — 헷갈리기 쉬운 차이

| | Glob | Grep |
|---|---|---|
| 찾는 것 | **이름**으로 파일 | 파일 **안의 줄** |
| 엔진 | glob 문법 (`**/*.ts`) | **ripgrep** 정규식 (POSIX grep 아님) |
| `.gitignore` | ⚠️ **무시함** (gitignore된 파일도 찾음) | ⚠️ **존중함** (건너뜀) |
| 결과 | 수정 시각 순, **100개 상한** | `files_with_matches`(기본) / `content` / `count` |

ripgrep 문법이라 메타문자를 이스케이프해야 한다. Go 코드에서 `interface{}`를 찾으려면 패턴이 `interface\{\}`.
gitignore된 파일을 검색하려면 경로를 직접 넘긴다.

#### 사용자가 컨텍스트를 넣는 방법

| 방법 | 설명 |
|---|---|
| `@경로` | 파일 참조. Claude가 응답 전에 읽는다 |
| 이미지 붙여넣기 | `Ctrl+V` (iTerm2는 `Cmd+V`, Win/WSL은 `Alt+V`). `[Image #N]` 칩이 삽입되어 위치 참조 가능 |
| URL 제공 | `/permissions`로 자주 쓰는 도메인 미리 허용 |
| 파이프 | `cat error.log \| claude -p "..."` |
| `!` 셸 모드 | 명령과 출력이 컨텍스트에 들어가고 Claude가 반응 |

### git 통합

#### 대화형 git

```
what files have I changed?
commit my changes with a descriptive message
create a new branch called feature/quickstart
show me the last 5 commits
help me resolve merge conflicts
```

**git 상태는 자동으로 컨텍스트에 들어간다** — 현재 브랜치, 미커밋 변경, 최근 커밋 히스토리가 시스템 프롬프트 끝에 별도 블록으로 로드된다.

#### ⚠️ `gh` CLI를 설치하라

공식문서가 명시적으로 권한다. CLI 도구는 외부 서비스와 상호작용하는 **가장 컨텍스트 효율적인** 방법이다. `gh`가 있으면 이슈 생성, PR 열기, 코멘트 읽기를 알아서 한다. 없으면 GitHub API를 쓰는데 비인증 요청은 rate limit에 걸린다.

Claude는 모르는 CLI 도구도 잘 배운다: `Use 'foo-cli-tool --help' to learn about foo tool, then use it to solve A, B, C.`

#### 변경 검토

```
/diff             # 인터랙티브 diff 뷰어
                  # ←→ 로 현재 git diff와 개별 턴 diff 전환, ↑↓ 로 파일 탐색
                  # ⚠️ 저장소 git 상태가 외부에서 바뀌면 자동 갱신 (v2.1.198+)
/code-review      # 현재 diff를 정확성·정리 관점에서 리뷰
/code-review high 1234        # PR 번호 지정
/code-review --fix            # 발견 사항 적용
/code-review --comment        # GitHub PR 인라인 코멘트로 등록
/code-review ultra            # ⚠️ 클라우드 멀티에이전트 심층 리뷰
/security-review  # 보안 취약점
```

#### ⚠️ PR 상태 뱃지

열린 PR이 있는 브랜치에서 작업하면 푸터에 `PR #446` 링크가 뜬다. 밑줄 색으로 리뷰 상태 표시:
초록=승인, 노랑=리뷰 대기, 빨강=변경 요청, 회색=드래프트.
`Cmd+click`(mac) / `Ctrl+click`으로 브라우저에서 열기. `gh` CLI 설치·인증 필요.
GitLab MR도 지원 (`glab` CLI 필요, v2.1.234+).

#### 귀속(attribution) 설정 ⚠️

```json
{
  "includeCoAuthoredBy": false,   // 커밋 메시지의 Co-Authored-By 라인
  "attribution": {
    "commit": "...",
    "pr": "...",
    "sessionUrl": "..."
  }
}
```

#### 병렬 작업 — worktree

```bash
claude -w feature-auth          # <repo>/.claude/worktrees/feature-auth 에서 시작
claude -w '#123'                # ⚠️ PR을 origin에서 가져와 그 위에 브랜치
claude -w feature-auth --tmux   # tmux 세션 생성
```

⚠️ `.worktreeinclude` 파일 (프로젝트 루트, `.gitignore` 문법)로 워크트리에 복사할 gitignore된 파일을 지정한다. 워크트리는 새 체크아웃이라 `.env` 같은 파일이 없기 때문.

```
# .worktreeinclude
.env
.env.local
config/secrets.json
```

#### 체크포인트 ≠ git (다시 강조)

체크포인트는 **세션 단위 빠른 복구**용이고 Bash로 한 변경은 추적하지 않는다. 영구 이력과 협업은 계속 git으로.

### 효과적인 작업 관리

#### 핵심 제약 하나만 기억한다면

> **컨텍스트 윈도우가 빨리 차고, 차오를수록 성능이 떨어진다.**
> 나머지 모범 사례는 대부분 여기서 파생된다.

#### 조기 교정 (course-correct early and often)

| 도구 | 용도 |
|---|---|
| `Esc` | 즉시 중단. 컨텍스트 보존됨 |
| `Esc` `Esc` / `/rewind` | 대화·코드 되감기 또는 부분 요약 |
| "Undo that" | Claude에게 되돌리게 하기 |
| `/clear` | 무관한 작업 사이 컨텍스트 초기화 |

**⚠️ 2번 규칙**: 한 세션에서 같은 이슈로 두 번 넘게 교정했다면, 컨텍스트가 실패한 접근들로 오염된 상태다. `/clear`하고 **배운 것을 반영한 더 구체적인 프롬프트로 새로 시작**하는 게 거의 항상 낫다.

#### 컨텍스트 공격적으로 관리하기

- 작업 사이에 `/clear`를 자주
- `/compact <초점>`으로 요약 방향 지정
- `Esc+Esc` → Summarize from here / up to here로 부분 압축
- `CLAUDE.md`에 압축 지시 넣기
- 컨텍스트에 남길 필요 없는 질문은 `/btw`

#### 서브에이전트에 조사 위임

```
Use subagents to investigate how our authentication system handles token
refresh, and whether we have any existing OAuth utilities I should reuse.
```

서브에이전트는 **자기 컨텍스트 윈도우**에서 일하고 요약만 돌려준다. 컨텍스트가 근본 제약이니 이게 가장 강력한 도구 중 하나다.

⚠️ `/btw`는 서브에이전트의 정반대다: **대화 전체를 보지만 도구가 없다**. 이번 세션에서 Claude가 이미 아는 것을 물을 땐 `/btw`, 새로운 걸 알아내야 할 땐 서브에이전트.

#### ⚠️ 태스크 목록 (Task list) — 동작이 바뀜

`Ctrl+T`로 토글하는 Claude의 할 일 체크리스트. 실행 중인 셸·서브에이전트를 보는 `/tasks`와는 **다른 것**이다.

> **Opus 4.8, Sonnet 5, Fable 5, Mythos 5 이상에서는 이 목록이 비어 있다.**
> 이 모델들은 별도 체크리스트 없이 다단계 작업을 추적하고, 도구 정의와 리마인더가 컨텍스트를 먹기 때문에 Claude Code가 아예 제공하지 않는다.
> 굳이 쓰려면 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`.

#### 세션을 브랜치처럼 쓰기

```bash
claude -n "oauth-migration"     # 이름 지정
/rename                          # 세션 중 이름 변경 (프롬프트 바에 표시)
claude --resume oauth-migration  # 이름으로 재개
```

각 작업 흐름에 자기만의 지속 컨텍스트를 준다.

#### 병렬 세션

| 방법 | 특징 |
|---|---|
| Worktrees | 격리된 git 체크아웃에서 별도 CLI 세션 |
| 데스크톱 앱 | 로컬 세션들을 시각적으로 관리, 각각 워크트리 |
| Claude Code on the web | 클라우드에서 실행 |
| ⚠️ Agent view (`claude agents`) | 리서치 프리뷰. 백그라운드 세션들을 한 화면에서 모니터링·디스패치 |
| ⚠️ Agent teams | 실험적, 기본 비활성. 공유 태스크와 메시징으로 여러 세션 자동 조율 |

**Writer/Reviewer 패턴** — 새 컨텍스트는 방금 자기가 쓴 코드에 편향되지 않으므로 리뷰 품질이 올라간다.

| 세션 A (Writer) | 세션 B (Reviewer) |
|---|---|
| `Implement a rate limiter for our API endpoints` | |
| | `Review the rate limiter in @src/middleware/rateLimiter.ts. Look for edge cases, race conditions, and consistency with existing middleware patterns.` |
| `Here's the review feedback: [B의 출력]. Address these issues.` | |

#### 파일 단위 팬아웃

```bash
# 1) 대상 목록 생성
#    "list all 2,000 Python files that need migrating and save the list to files.txt"

# 2) 루프
for file in $(cat files.txt); do
  claude -p "Migrate $file from Python 2 to Python 3. Return OK or FAIL." \
    --allowedTools "Edit,Bash(git commit *)"
done

# 3) 2~3개로 프롬프트 다듬고 전체 실행
```

⚠️ git 저장소라면 `/batch <지시>`가 이걸 대신해준다 — 작업을 5~30개 독립 단위로 분해해 각각 별도 워크트리의 백그라운드 서브에이전트로 돌리고 PR을 연다.

#### ⚠️ 적대적 리뷰 단계 추가

```
Use a subagent to review the rate limiter diff against PLAN.md. Check that
every requirement is implemented, the listed edge cases have tests, and
nothing outside the task's scope changed. Report gaps, not style preferences.
```

> **주의**: 갭을 찾으라고 지시받은 리뷰어는 작업이 멀쩡해도 대개 뭔가를 보고한다. 모든 지적을 쫓으면 과잉 설계로 간다 — 불필요한 추상화 계층, 방어적 코드, 일어날 수 없는 케이스의 테스트. **정확성이나 명시된 요구사항에 영향을 주는 갭만 표시하라고 지시하고, 나머지는 선택 사항으로 취급.**

#### 흔한 실패 패턴 5가지

| 패턴 | 증상 | 해결 |
|---|---|---|
| **잡탕 세션** | 한 작업 하다 무관한 질문 하고 다시 돌아옴 | 작업 사이 `/clear` |
| **반복 교정** | 틀림 → 교정 → 또 틀림 → 또 교정 | 2번 실패 후 `/clear` + 더 나은 초기 프롬프트 |
| **과잉 명세 CLAUDE.md** | 너무 길어서 중요한 규칙이 소음에 묻힘 | 가차없이 쳐내기. 지시 없이도 잘하면 삭제, 반드시 지켜야 하면 훅으로 |
| **신뢰-검증 갭** | 그럴듯한데 엣지 케이스 처리 안 됨 | 항상 검증 제공. 검증 못 하면 배포하지 않기 |
| **무한 탐색** | 범위 없이 "조사해줘" → 수백 파일 읽고 컨텍스트 폭발 | 범위를 좁히거나 서브에이전트로 |

#### CLAUDE.md에 넣을 것 / 뺄 것

| ✅ 넣기 | ❌ 빼기 |
|---|---|
| Claude가 추측할 수 없는 Bash 명령 | 코드 읽으면 알 수 있는 것 |
| 기본값과 다른 코드 스타일 규칙 | 표준 언어 컨벤션 |
| 테스트 방법과 선호 러너 | 상세 API 문서 (링크로) |
| 저장소 에티켓 (브랜치명, PR 컨벤션) | 자주 바뀌는 정보 |
| 이 프로젝트 고유의 아키텍처 결정 | 긴 설명·튜토리얼 |
| 개발 환경 특이사항 (필수 env var) | 파일별 코드베이스 설명 |
| 흔한 함정, 비자명한 동작 | "깨끗한 코드를 쓰자" 같은 자명한 것 |

각 줄마다 물어보라: **"이 줄을 지우면 Claude가 실수하게 되나?"** 아니면 지운다.

⚠️ 규칙 하나를 계속 무시하면 **그 줄에만** "IMPORTANT"를 붙인다. 여러 줄을 강조하면 어느 것도 눈에 띄지 않는다.

## 부록 B. 스터디 준비용 실습 소재

우리 스터디 규칙(① 챕터를 적용해본 사례, 또는 ② 공식문서에서 찾은 내용/좋은 사례 하나)에 맞춰 쓸 만한 것들.

### 바로 해볼 수 있는 실습

1. **`/context` 스크린샷 떠오기** — 우리 프로젝트에서 세션 시작 직후 `/context`를 찍고, 뭐가 얼마나 먹고 있는지 발표. `CLAUDE.md`가 몇 토큰인지, MCP가 몇 토큰인지 실제 숫자로 보면 감이 온다.
2. **`/doctor` 돌려보고 제안 확인** — 특히 `CLAUDE.md` 다이어트 제안이 뭘 자르라고 하는지. 자동으로 "코드베이스에서 유추 가능한 내용"을 판별해준다.
3. **`.claude/rules/` 도입해보기** — 기존 `CLAUDE.md`에서 특정 디렉토리에만 해당하는 규칙을 `paths:` 룰로 분리하고, 컨텍스트가 얼마나 줄었는지 `/context`로 비교.
4. **Auto memory 폴더 열어보기** — `/memory` → auto memory 폴더. Claude가 나에 대해 뭘 적어놨는지 확인. 발표 소재로 재밌음.
5. **압축 생존 실험** — 대화로만 지시를 준 뒤 `/compact`하고 그 지시가 살아있는지 확인. `CLAUDE.md`에 넣은 지시와 비교.
6. **`--bare` vs 일반 `-p` 비교** — 같은 프롬프트를 두 방식으로 돌리고 시작 시간·컨텍스트 차이 측정.
7. **`/rewind`의 Summarize up to here** — 긴 디버깅 세션 중간에서 앞부분만 압축해보기.
