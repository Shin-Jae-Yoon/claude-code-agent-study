    SECTION 01

    개념과 아키텍처

    서브에이전트가 무엇이고, 왜 컨텍스트 격리가 전부인가

    한 줄 정의

    Agent 도구로 띄우는 별도 Claude 인스턴스

    자기만의 컨텍스트 윈도우, 자기만의 시스템 프롬프트, 자기만의 도구 권한을 가진다.

    중간 도구 호출과 그 결과는 전부 서브에이전트 안에 남고, 부모에게는 최종 메시지 한 개만 Agent 도구의 결과로 돌아온다.
    컨텍스트 보존

    탐색과 구현을 메인 대화 밖에 둔다

    병렬화

    독립 하위 작업이 합이 아니라 최댓값의 시간에 끝난다

    최소 권한

    에이전트별로 도구를 제한한다

    → 이 셋은 전부 "작업은 안에서, 결론만 밖으로" 하나에서 파생된다.

    스킬 vs 서브에이전트

    무엇을 알아야 하는가 / 어떻게 수행하는가

    스킬 (Skill)서브에이전트 (Subagent)

    실행 위치메인 대화 컨텍스트 안격리된 별도 컨텍스트
    결과대화에 그대로 누적요약만 반환

    오케스트레이터–워커

    리드는 마이크로매니징하지 않는다

    명확히 정의된 작업만 넘기고 결과를 종합한다. Anthropic Research 기능이 쓰는 패턴과 같다.

    멀티에이전트가 잘 되는 이유의 상당 부분은 "병렬로 더 많이 생각할 수 있어서"다. 결과의 가치가 15배 토큰을 정당화할 때만 쓴다.
    설계 원칙

    단일 책임, 그리고 5~7개의 로스터

    작동하는 로스터의 3조건

    • 하나의 job
    • 그 job에 필요한 최소 도구
    • 리드가 병합하기 좋은 고정된 반환 형태

    안 되는 것

    • 만능 에이전트 하나
    • 30개짜리 난립 — 서로의 수정을 밟는다
    • 반환 형태가 매번 다른 에이전트

    공식 Best practices 첫 줄: "각 서브에이전트는 하나의 특정 작업에 탁월해야 한다."

    컨텍스트 엔지니어링

    적정 고도 (right altitude)

    시스템 프롬프트를 쓸 때의 골디락스 존. 두 가지 실패 모드 사이.

    너무 낮음

    if-else 하드코딩, 브리틀한 분기 나열. 취약하고 유지보수 비용이 폭발한다. 예상 못 한 상황에서 깨진다.

    적정 고도

    행동을 유의미하게 제약하되, 스크립트하지 않은 상황도 판단할 수 있게. 워크플로는 고정하고 판단은 남긴다.

    너무 높음

    "코드를 잘 리뷰해라". 구체적 신호가 없고, 없는 공유 맥락을 있다고 가정한다.

    공식 권고: 프롬프트를 <background_information>, <instructions>, ## Tool guidance, ## Output description 섹션으로 구조화할 것.

    컨텍스트 격리

    서브에이전트가 시작할 때 받는 것 / 못 받는 것

    받음못 받음
    자기 시스템 프롬프트 + Agent 도구의 프롬프트부모의 대화 기록·도구 결과
    CLAUDE.md 계층 전체 Explore/Plan 제외부모의 시스템 프롬프트
    git status 스냅샷 Explore/Plan 제외메인 대화의 auto memory
    skills:에 명시한 스킬 전문이미 호출된 스킬 내용
    도구 정의 (상속 또는 부분집합)output style
    부모 → 서브에이전트로 가는 유일한 통로는 Agent 도구의 프롬프트 문자열이다. 파일 경로, 에러 메시지, 이미 내린 결정은 그 프롬프트에 직접 다 넣어야 한다.
    책과 다름

    "각 서브에이전트가 독립적인 20만 토큰 컨텍스트"

    방향은 맞지만 숫자는 고정값이 아니다.

    서브에이전트의 컨텍스트 윈도우 크기는 부모가 아니라 자기 모델이 결정한다. 더 작은 윈도우를 가진 모델에 위임하면 그 서브에이전트는 작은 윈도우를 갖는다.
    • model: haiku로 띄운 서브에이전트와 메인 Opus 세션의 윈도우는 다르다
    • 정확한 서술: "독립적인 컨텍스트 윈도우를 갖는다". 200K는 모델별 값일 뿐
    • 서브에이전트도 auto-compaction을 지원한다. 트랜스크립트에 compact_boundary 이벤트가 남는다
    내장 서브에이전트

    커스텀을 만들기 전에 이것부터

    이름모델도구용도
    Explore메인 상속 v2.1.198 변경읽기 전용파일 탐색, 코드 검색
    Plan메인 상속읽기 전용plan mode의 코드베이스 리서치
    General-purpose메인 상속전부탐색+수정이 함께 필요한 다단계 작업
    패턴

    읽기 전용 리서치 에이전트는 가볍고 싸게, 만능 에이전트는 메인 모델과 전체 도구를 상속. 최소권한 아이디어가 내장 에이전트에 이미 인코딩되어 있다.

    주의

    Explore/Plan은 CLAUDE.md와 git status를 일부러 건너뛴다. "vendor/ 무시" 같은 규칙이 꼭 필요하면 위임 프롬프트에 다시 적어야 한다.

    Explore를 Haiku로 고정하려면 → 같은 이름 Explore로 커스텀 정의를 만들어 내장을 덮어쓴다.

    판단 기준

    언제 위임하고, 언제 메인에 머무는가

    서브에이전트

    • 메인 컨텍스트에 필요 없는 장황한 출력이 나오는 작업
    • 도구·권한 제한을 강제하고 싶을 때
    • 작업이 자기완결적이고 요약으로 반환 가능

    메인 대화

    • 잦은 왕복이나 반복적 다듬기
    • 계획→구현→테스트처럼 여러 단계가 같은 맥락을 공유
    • 빠르고 좁은 수정
    • 레이턴시가 중요할 때 (콜드스타트)
    부산물이 크고 결론이 작으면 위임한다. 맥락이 공유되고 상호작용이 빡빡하면 메인에 머문다.

    대화에 이미 있는 내용에 대한 곁가지 질문은 서브에이전트가 아니라 /btw. 전체 컨텍스트를 보되 도구 접근이 없고, 답이 히스토리에 남지 않는다.

    책에 없음

    fork — 대화 전체를 상속하는 서브에이전트

    /subtask <작업>으로 실행. 인터랙티브 세션에선 fork mode가 기본 on.

    fork일반 서브에이전트
    컨텍스트대화 기록 전체전달한 프롬프트만
    시스템 프롬프트·도구메인과 동일정의 파일에서
    모델메인과 동일model 필드
    프롬프트 캐시메인과 공유별도
    입력 격리는 포기하고 출력 격리만 취한다. 시스템 프롬프트와 도구 정의가 부모와 같아 첫 요청이 부모의 프롬프트 캐시를 재사용한다 — 같은 맥락이 필요한 작업이면 새 서브에이전트보다 싸다.

    description은 "언제"를 쓰는 자리다

  Proactively reviews code for quality,

  Use immediately after writing or
  modifying code.

    resume

    • 완료된 서브에이전트가 SendMessage를 받으면 새 Agent 호출 없이 auto-resume
    • 단 내가 직접 멈춘 것은 auto-resume 되지 않는다 v2.1.191

    SECTION 03

    커스텀 개발과 스킬 주입

    프론트매터 · skills 필드 · 스킬 조합 · 프롬프트 작성

    정의 파일

    필수는 딱 둘, 나머지는 전부 선택

    ---
name: code-reviewer            # 필수
description: Reviews code...   # 필수 — 위임 판단의 근거
tools: Read, Glob, Grep        # 사실상 필수 (최소권한)
model: sonnet                  # 사실상 필수 (비용)
---

You are a code reviewer. When invoked, analyze the code and provide
specific, actionable feedback on quality, security, and best practices.
    • 프론트매터 = 구성 / 본문 = 시스템 프롬프트. Claude Code의 전체 시스템 프롬프트는 상속하지 않는다
    • 파일명은 name과 달라도 된다. 식별자는 name뿐
    • name 없으면 문서로 간주해 조용히 스킵, description 없으면 디버그 로그에만 → --debug 없이는 모른다
    • 사전 점검: claude plugin validate .claude/agents v2.1.233

    • 장애 보고 규약. 조용히 부분 결과를 돌려주지 말고 무엇이 막았는지 보고
    • 최소 도구. code-reviewer엔 Edit 없이, debugger엔 Edit 있게

    SECTION 06

    CLI 기반 동적 에이전트

    --agent · --agents · 해석 순서 · 팀과의 관계

    --agent

    메인 스레드 자체를 특정 역할로

    claude --agent code-reviewer
    • 서브에이전트의 시스템 프롬프트가 기본 Claude Code 프롬프트를 완전히 대체한다
    • CLAUDE.md와 프로젝트 메모리는 정상 메시지 흐름으로 여전히 로드된다
    • 시작 헤더에 @<name>으로 표시. 세션을 재개해도 유지된다
    • .claude/settings.json의 "agent"로 프로젝트 기본값. CLI 플래그가 우선

    이때만 쓸 수 있는 문법 — 스폰 화이트리스트

    tools: Agent(worker, researcher), Read, Bash

    worker와 researcher만 스폰 가능. ⚠️ 이 괄호 문법은 --agent로 메인 스레드일 때만 적용된다. 서브에이전트 정의에선 괄호 안 타입 리스트가 무시된다.

    해석 순서

    정의 · 모델 · 도구가 각각 다르게 해석된다

    정의 스코프

    프로젝트는 cwd→루트로 스캔. 동명이면 cwd에 가장 가까운 것이 이긴다

    모델 
    1 CLAUDE_CODE_SUBAGENT_MODEL

4 메인 대화 모델

    도구

    fork는 두 필터를 모두 건너뛰고 메인 대화의 정확한 도구 풀을 받는다.

    --agents

    인라인 정의 — 세션 한정, 디스크에 안 남음

    claude --agents '{
  "code-reviewer": {
    "description": "Expert code reviewer. Use proactively after code changes.",
    "prompt": "You are a senior code reviewer...",
    "tools": ["Read", "Grep", "Glob", "Bash"],
    "model": "sonnet"
  },
  "debugger": { "description": "...", "prompt": "..." }
}'
    • 빠른 테스트, 자동화 스크립트, CI에 적합. 한 번에 여러 개 정의 가능
    • prompt가 파일 기반의 마크다운 본문에 해당
    • -p에선 팀이 안 생긴다 → CI 파이프라인이 개발자 로컬 설정에 흔들리지 않는다
    • --strict-mcp-config는 --agents의 인라인 서버를 필터링하지 않는다 (명시적 caller input)

    ⚠️ --bare는 훅·스킬·서브에이전트·플러그인·MCP·CLAUDE.md의 자동 발견을 전부 건너뛴다. 빠르게 하려다 에이전트가 안 잡히는 일이 흔하다.

    SECTION 07

    세션 간 메시징

    v2.1.224+ · 조건을 만족하면 켤 것 없이 이미 켜져 있다

    사다리의 마지막 칸

    내가 직접 띄운 세션들끼리

    1서브에이전트 — 한 세션 안의 워커
    2에이전트 팀 — Claude가 스폰하고 감독하는 세션들
    3cross-session — 내가 직접 띄우고 조종하는 독립 세션들 ← 비어 있던 칸
    메시지는 한 Claude가 다른 Claude에게 쓴 텍스트 한 조각이다. 절대 대화 기록이나 파일이 아니다. 통째로 옮기려면 세션을 resume하는 게 맞는 도구다.

    도구 둘: ListAgents(발견) / SendMessage(배달). 사용자가 직접 호출하지 않는다. 같은 SendMessage가 서브에이전트·팀메이트에도 쓰인다 → deny하면 셋 다 꺼진다.

    사용

    내용은 Claude가 쓴다

    # 내가 치는 프롬프트
Ask the session running in my other terminal whether the migration finished

Explain what we just did to the session working on the payments API

Let @api-worker know the schema migration finished    # @-멘션으로 타깃 지정
    # 받는 쪽에 도착하는 것
Schema migration finished: the new column is tenant_id, and rebasing on main is safe now.
    • 수신 Claude는 도구 호출 사이에 읽는다 → 실행 중인 도구는 절대 중단되지 않는다
    • 수신 세션이 idle이면 그 메시지로 새 턴을 시작한다
    • 배달되면 내가 타이핑한 프롬프트처럼 usage에 카운트된다
    • 세션 이름은 --name/-n 또는 /rename. 충돌하면 기존 세션이 이름을 지킨다
    보안 모델

    권한 경계는 세션별로 유지된다

    수신 세션에게 사용자가 아니라 다른 Claude 세션에서 왔다고 알리고 제한한다.

    아무것도 승인할 수 없다다른 세션의 메시지는 절대 내 동의로 치지 않는다. 대기 중인 권한 프롬프트를 대신 답할 수 없다
    설정을 바꿀 수 없다다른 세션이 요청했다는 이유로 권한 설정·CLAUDE.md·구성을 바꾸지 말라고 지시받는다
    커맨드가 실행되지 않는다메시지 안의 /compact 같은 건 평문으로 도착한다
    권한 프롬프트는 그대로행동에 권한이 필요하면 평소와 똑같은 프롬프트가 뜬다
    발신 측도: 자기 세션에서 거부·차단된 행동을 다른 세션에 요청하지 말고 사용자에게 되돌리라고 지시받는다.
    inbound 제어

    기본 규칙은 bypass 세션을 조인다

    crossSessionInbound동작
    accept각 메시지를 Claude에게 배달
    hold알림만 표시하고 배달 안 함. 이후 accept가 적용되면 방출
    refuse배달 없이 드롭

    값이 없을 때 — 두 세션의 권한 모드 클래스로 판단

    수신이 묻는 쪽각 메시지를 배달. 단 발신이 bypass라고 밝히면 승인 대기로 보류
    수신이 bypass 쪽각 메시지를 보류. 발신도 bypass일 때만 배달
    논리: bypass 세션으로 들어가는 메시지가 명백한 실패 모드다. 승인 없이 뭐든 실행하는 세션에 외부 텍스트가 들어가는 것이니 그쪽을 조인다.

    보류 다이얼로그 기한 dialogExpiry 기본 5분. 보류는 최대 100통. 루프는 rate limit + 동일 반복 드롭 + 큐 50통 상한으로 저절로 멈춘다.

    경로와 함정

    어디를 거쳐 가는가 · 왜 안 되는가

    상대 위치경로
    이 머신세션별 Unix 소켓 / named pipe. Anthropic 서버를 거치지 않는다
    내 다른 머신Anthropic 서버 경유 → 그 머신의 Remote Control 연결로
    Claude Code on the webAnthropic 서버 경유 → 클라우드 세션으로
    도달 못 하는 조합

    같은 머신 배달은 디스크의 등록 파일을 읽어 서로를 찾는다 → 컨테이너 안 세션과 호스트 세션은 서로 못 본다. WSL 2 세션과 네이티브 Windows 세션도 마찬가지.

    실무 함정

    DISABLE_TELEMETRY, DO_NOT_TRACK, DISABLE_GROWTHBOOK, CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC 중 하나라도 기능 플래그 평가를 끄면 메시징도 꺼진다. 사내 보안 설정에서 흔히 켜는 것들.

    Bedrock / Claude Platform on AWS / Google Cloud Agent Platform / Microsoft Foundry에선 사용 불가. 진단은 /list-agents가 인식되는지부터.

    부가 기능

    idle 알림 구독 v2.1.236

    Tell me when the migration session finishes what it's working on
    • Claude가 SendMessage의 notify_when_idle로 구독. 메시지에 붙이거나 단독으로
    • 단독이면 감시 대상 세션에서 턴을 시작하지도, 토큰을 쓰지도 않고 구독한다. 이미 idle이면 즉시 통지
    • 일회성. 12시간 내 통지가 없으면 구독을 버리고 Claude에게 알린다 → 무한 대기하지 않는다
    • 메인 대화의 Claude만, 같은 머신 세션에만 구독 가능. 서브에이전트·팀메이트는 불가

    스크립트 연동 — 훅과 Bash 명령에 CLAUDE_CODE_MESSAGING_SOCKET과 CLAUDE_CODE_MESSAGING_TOKEN이 export된다. 자기 세션 소켓에 포스트할 때 첫 줄로:

    {"type":"auth","token":"<CLAUDE_CODE_MESSAGING_TOKEN>"}

    macOS/Linux/WSL2는 선택, 네이티브 Windows는 필수. /status의 Peer address 행에서 소켓 경로 확인.
